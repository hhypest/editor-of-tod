# ADR-0006: предметные модули и независимые прикладные сценарии

Дата: 02.10.2026. Статус: принято направление; сценарий копий восстановления реализован в CR5, границы review — в А3; остальные сценарии уточняются по дорожной карте.

## Контекст

Редактор работает локально, для одного составителя, на Vue / TypeScript и SQLite. Предметная модель уже выражена снимками Scheme и чистыми функциями. Часть прикладной логики объединена с Vue-сессией и хранилищем, до А3 результаты проверки содержали цели DOM. Полное перестроение проекта задержало бы предметную приёмку без доказанного выигрыша.

## Решение

Развиваем модульный монолит. Правила DDD применяем к языку, допустимым изменениям и согласованности данных; Clean Architecture — к направлению зависимостей. Данные и чистые функции остаются допустимой формой модели.

- `src/domain` описывает данные схемы и предметные правила без Vue, DOM, HTTP и SQLite. Результат проверки содержит предметный путь; цель перехода определяется по пути и устойчивому коду в адаптере представления (А3).
- `src/application` координирует прикладные сценарии и определяет узкие интерфейсы необходимых операций. Модуль не импортирует компоненты, composables, `services` или серверное хранилище.
- Компоненты и composables владеют вводом, реактивным состоянием и временем запуска операции. `src/services` реализует клиентские HTTP-адаптеры. Серверные адаптеры отвечают за транспорт и SQLite; согласованные изменения сохраняют транзакционные проверки.
- Схема, реестр ПУ-66 и нормативная библиотека — кандидаты на предметные модули. Отдельные bounded contexts выделяются при выявлении разных моделей, языка и правил; общая SQLite допустима. Каждый реестр не становится автоматически отдельным контекстом.
- Следующие сценарии для выделения — сохранение проекта, восстановление редакции и жизненный цикл ПУ-66 (А4). Разделение RegistryStore выполняется по областям ответственности с сохранением атомарности.
- При П3 проект закрепляет нормативное основание решения; проверка по актуальным правилам остаётся отдельной операцией. При Р1 типы различают метры и координаты листа.

Не вводим универсальные репозитории, обязательные базовые классы сущностей, CQRS, Event Sourcing или DI-фреймворк без конкретного сценария, который окупает их сложность.

## Первый реализованный сценарий: CR5

`RecoverySession` через `RecoveryRepository` сериализует запись, захват, продление владения, освобождение и удаление копий. Vue-сессия задаёт задержку записи и обновляет интерфейс. Контракт HTTP восстанавливает ссылку на исходный JSON перед полной валидацией Scheme; транспортный контракт не меняет JSON проекта v7.

SQLite v13 добавляет владельца окна и срок активности копии. Запись продлевает срок; отдельное продление каждые 20 секунд не меняет содержимое, дату правки и версию. Срок — 120 секунд. Закрытие, перезагрузка и переход к другому проекту освобождают копию; аварийное закрытие допускает восстановление после истечения срока. Это координация локальных окон, а не аутентификация пользователя.

Захват проверяет ожидаемую версию внутри `BEGIN IMMEDIATE`, назначает нового владельца и увеличивает контрольную версию. Запоздалые запросы прежнего окна не могут записать или удалить переданную копию. Продление и освобождение действуют только для своего владельца. Замороженное браузером окно может потерять владение: при возврате программа показывает ошибку и сохраняет его правки в памяти; автоматического объединения нет.

Первый снимок импортированной схемы передаёт исходный JSON, ответ содержит только версию, дату и SHA-256. Следующие записи этой же копии передают ссылку; сервер допускает только источник, уже связанный с ней. Открытие, экспорт и сохранённые версии остаются самодостаточными. После удаления копии клиент забывает ссылку.

## Реализованная граница review: А3

Результаты проверки содержат предметный путь, а не CSS-идентификаторы и data-field. Отдельный UI-маппер выбирает этап и поле, неизвестный путь возвращает к списку проверки. Коды, kind, тексты и basis не менялись: действующие отпечатки «Проверено» сохраняются. Общая интерпретация кодов знаков вынесена в sign-code; review, закрепление PNG и рисунок независимы от реализации друг друга.

Golden snapshots сняты до переноса на пяти вымышленных старых JSON. Проверки путей к полям находятся в presentation-тестах, без зависимости domain-тестов от компонентов. check:architecture проверяет разрешённые пути, в том числе алиас @/, и циклы; отрицательные примеры проверяют запреты. Форматы проекта v7 и SQLite v13 не меняются. [Baseline и пределы проверок](../refactoring-contracts.md).

## Проверка и последствия

ESLint запрещает зависимости domain/application от Vue, браузерных глобальных объектов, клиентских и серверных адаптеров; domain также не импортирует application. Это проверяется в `npm run check`. Прикладные тесты проверяют очередь записи, сбои и версии без Vue и сервера. SQLite / API проверяют владельцев, истечение срока, конкурирующий захват, старые запросы и сохранность данных при миграции. Браузерный сценарий проверяет две вкладки, неприменённый ввод и состав HTTP-запросов.

Перед обновлением остановить программу и сохранить копию SQLite. Программы, поддерживающие базу до v12, обновлённую v13 не открывают; откат требует заранее сохранённой копии. Копии восстановления не заменяют явное сохранение редакции и резервную копию базы.

## Пересмотр

При появлении нескольких пользователей, второго клиента или процесса согласования уточнить границы контекстов, авторизацию и долгоживущие сценарии. Сложность инфраструктуры добавлять после появления соответствующих требований.
