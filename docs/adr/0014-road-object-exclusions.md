# ADR-0014: обратимое исключение связанной стойки

Статус: реализованный отдельный срез П6; автоматические правила и предметная приёмка остаются очередью.

Дата: 02.11.2026. Задача: [#107](https://github.com/hhypest/editor-of-tod/issues/107). Предыдущая геометрия — [ADR-0013](0013-branch-post-placement.md).

## Причина и границы

Удаление связанной стойки теряло её связь и введённые данные. Для последующих предложений и ручных исключений нужен сохраняемый результат явного удаления. Этот срез реализует обратимое исключение существующей связанной стойки. Он не присваивает старому объекту автоматическое происхождение и не выбирает правило по сходству рисунка.

Несвязанные объекты удаляются прежней командой; восстановление общей отменой остаётся доступным. Автоматические/изменённые объекты, стабильные ключи правил и предложений, применение расчётного варианта и отсоединение при удалении узла по РП4 — следующие срезы. РП1–РП7 целиком этим изменением не закрываются.

## JSON v14

Необязательный `roadObjectExclusions` содержит:

| Поле             | Содержание                                                                    |
| ---------------- | ----------------------------------------------------------------------------- |
| `objects`        | Непустой список полных снимков `post` и `link` исключённых стоек              |
| `placementOrder` | Порядок IDs объектов для восстановления, независимо от их числовой сортировки |
| `linkOrder`      | Порядок placement IDs связей для восстановления                               |

Снимки проходят тот же текущий контракт стойки и связи. Исключённый ID не занят активным объектом, меньше nextPlacementId, совпадает с link.placementId и не повторяется. Узел существует; роль/ветвь согласованы с ним. Порядки уникальны и содержат исключённые IDs. Вместе активных и исключённых объектов не более 2000. Прежние сведения об удалённых несвязанных IDs в порядках не резервируют их и при следующем исключении убираются.

Команда исключения убирает post из placements и link из roadLayout.links, сохраняя полные снимки и прежний порядок. Следующий ID не меняется. Явное восстановление возвращает оба снимка одной операцией, сохраняя порядок при нескольких исключениях и новых добавлениях. При последнем восстановлении поле исключений удаляется. Текущее относительное размещение на ветви снова следует своему узлу; из условных координат не восстанавливаются метры.

## Сохранность рисунка и изображений

Исключённые стойки не входят в предметные проверки, перечень используемых на листе знаков, габариты, коллизии, SVG и PNG. Их сохранённые расстояния используются только как прежние входы условной шкалы, чтобы исключение не переставляло остальные стойки или узлы. Нормативных выводов из этих неактивных расстояний нет.

Сравнение набора знаков при сбросе закреплений и явное закрепление каталога учитывают также исключённые стойки. Само исключение/восстановление не сбрасывает каталог и версии PNG. Для рисунка загружаются активные знаки; после восстановления снова используются сохранённые закрепления. Исходник, снимок ПУ-66, evidence и отметки не переписываются командой.

## UI, история и recovery

Для связанной стойки кнопка называется «Исключить стойку». Под свойствами показан список с ID, узлом и кодами знаков и явной кнопкой восстановления. До применения/отмены неприменённого ввода обе команды закрыты. Каждая команда использует одну операцию существующей истории; схема с исключениями попадает в прежнюю recovery-копию. Новых очередей, сессий, таймеров и таблиц нет.

Исключённая связь продолжает защищать узел от удаления. Несовместимое изменение стороны узла отклоняется; отступ совместимого узла можно изменить, и восстановленная стойка использует записанные относительные координаты. Политика отсоединённых объектов по РП4 требует отдельной реализации.

## Совместимость и проверка

JSON повышен до v14, SQLite остаётся v13. Читатель v13 и road-layout-v13 зафиксированы независимо. Миграция меняет только номер оболочки, не создаёт исключений и не выводит удалённые объекты из originalJson. Чтение прежней истории не переписывает SQLite; явное сохранение создаёт новую редакцию. Старые fixtures/expected/контрольные суммы сохранены; v14 добавлен отдельно на вымышленных данных.

Проверяются полный round-trip, зарезервированные IDs, исходный несортированный порядок и несколько исключений, неподвижность остальных объектов, PNG pins, одна отмена/повтор, SQLite/history/recovery и реальное отсутствие/возврат программно нарисованного знака в PNG. Общая защита перестройки/выпуска native/raw остаётся. Полная П6, J01–J04 и R07/#109 не объявляются принятыми.
