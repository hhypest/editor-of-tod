Дополнен отсутствовавший явный контракт будущей версии: [database-contracts](../../server/__tests__/database-contracts.test.ts) фиксирует побайтовую неизменность файла, отсутствие backup и повторное открытие после отказа. Он проходит на исходном RegistryStore до переноса connection lifecycle.

Первый перенос: `database/connection.ts` владеет открытием, правами и защитными настройками SQLite. Миграции, backup, SQL областей и HTTP пока остаются в RegistryStore/старых маршрутах. [Прямые проверки подключения](../../server/__tests__/database-connection.test.ts) проверяют отсутствие скрытой миграции, foreign keys, запрет расширений, закрытие при ошибке настройки и повторное открытие файла. Timeout остаётся 3000 мс.

После исходного блока выделены резервные копии (#197), [миграции](sqlite-migrations.md), [ProjectSourceStore](project-source-store.md), [ProjectRepository](project-repository.md), [RecoveryRepository](recovery-repository.md), [ручные реестры](legacy-registry-repository.md), [чтение/ключи ПУ-66](pu66-read-repository.md) и [журнал сверок](pu66-verification-repository.md). Прямые проверки и предварительные контракты фасада фиксируют границы каждой области; для ПУ-66 — read-only соединение, старые ключи, точные поля/типы и metadata. Сверки дополнительно проверены до переноса через фасад и напрямую: порядок отказов, блокировка проверки статуса и откат записи, порядок истории и повторное открытие. Lifecycle выделен в [repository/service](pu66-lifecycle.md): повторный план под блокировкой, атомарный пакет и узкий backup port; предварительные контракты фасада и прямые проверки сохранены. Дальше: импорт ПУ-66 и остальные repositories/application services → маршруты по [плану](server-god-object-plan.md). Пробелы тестов добавляются при переносе ответственности; snapshots и ожидания не обновляются ради прохождения переноса.
