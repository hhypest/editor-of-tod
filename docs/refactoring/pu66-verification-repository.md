# Хранение журнала сверок ПУ-66 (#135)

`server/pu66/verification-repository.ts` владеет записью и чтением существующего журнала сверок: `record/list`, SQL и row mapper. Это очередной перенос по [ADR-0010](../adr/0010-modular-server-persistence.md), после [чтения карточек и ключей](pu66-read-repository.md). Журнал остаётся частью модуля ПУ-66 в одной SQLite.

## Сохранённый порядок операции

1. Прежняя схема проверяет входные данные и обрезает пробелы имени специалиста.
2. Общий resolver разрешает текущий ключ/alias; отсутствие ключа возвращает `null`, неоднозначность — прежнюю ошибку.
3. Время получается один раз. Сверка будущей местной календарной датой отклоняется до открытия транзакции.
4. В `BEGIN IMMEDIATE` заново читается текущая редакция карточки. Отсутствие строки возвращает `null` с откатом; несовпадение expectedRevision отклоняется перед проверкой исключения.
5. Проверка исключения выполняется на том же соединении внутри блокировки; затем запись журнала фиксируется. Ошибка чтения статуса или вставки откатывает транзакцию.

Каждая успешная команда добавляет запись, включая повтор одинаковых данных. История содержит все редакции и сортируется по id DESC, а не по дате сверки. Выбор текущей сверки для списка карточек остаётся отдельным прежним запросом: текущая редакция, verified_at DESC/id DESC. Запись журнала не переписывает карточку, её редакции, проекты или исходник.

## Переходная граница зависимостей

Репозиторий получает соединение, узкий `resolve`, запрос `(key) => { excluded: boolean } | null` и часы. Он не импортирует RegistryStore, HTTP, миграции или backup, не открывает и не закрывает соединение. Временный фасад делегирует два прежних метода, передаёт `() => this.now()` с сохранением receiver часов и подключает существующий getPu66Status. Вызов статуса остаётся в прежнем месте транзакции, без копирования lifecycle SQL. При следующем выделении lifecycle будет заменена реализация этого запроса.

InvalidPu66Verification и InvalidPu66Lifecycle перенесены в `server/pu66/errors.ts`; старые экспорты фасада ссылаются на те же конструкторы и сообщения. Порядок отказов и HTTP-коды остаются прежними. SQL и строковые сообщения перенесены без изменения. Форматы JSON v10/SQLite v13, белые списки #110, нормативные алгоритмы и лист сохранены.

Ежегодное переутверждение карточек относится к организации и специалисту, находится вне ответственности репозитория/разработчика и не является условием разработки или выпуска. Этот перенос выделяет хранение уже существующего локального журнала и не меняет распределение ответственности.

## Проверки и продолжение

- [Два контракта фасада](../../server/__tests__/pu66-verification-contracts.test.ts) прошли до переноса: receiver часов, порядок отказов, история по вставке и откат после ошибки SQLite trigger.
- [Прямые SQLite-проверки](../../server/__tests__/pu66-verification-repository.test.ts) используют вымышленные данные без RegistryStore: missing/empty/dangling/aliases, общие конструкторы ошибок, валидация и дата до BEGIN, редакция перед статусом, блокировка второго соединения во время проверки статуса, повторные/задним числом записи разных редакций, повторное открытие, read-only история, ошибки статуса/вставки и сохранность карточек/истории.
- Сохраняются прежние API/lifecycle/import/frozen-format тесты и полный E2E. Настройка busy_timeout = 1 мс применяется только к конкурирующему тестовому соединению; программа использует прежние 3000 мс.
