# Нормативные документы и связи изменений (#135)

`server/documents/normative-document-repository.ts` владеет SQL и row mapper библиотеки: list/get/findBySha/getPdf, вставка PDF с метаданными и обновление реквизитов. `normative-document-service.ts` владеет проверкой входа, дубликатов SHA, связей изменений и запретом смены вида документа при ссылке из истории каталога знаков. Это следующий шаг после [импорта ПУ-66](pu66-import.md) по [ADR-0010](../adr/0010-modular-server-persistence.md).

## Сохранённые контракты

- Список сортируется прежним SQL по code/effective_from/id. Get/findBySha по-прежнему используют этот список; отдельный оптимизирующий запрос не добавлен. Row mapper и порядок свойств сохранены. Метаданные не содержат PDF; getPdf возвращает прежние filename/bytes либо null.
- Add сначала разбирает documentMetaSchema, затем проверяет duplicate SHA и amendsId. Сохраняются точные PDF, имя, SHA, byteLength и одно время добавления. Конструктор фасада передаёт часы с прежним receiver. Правка метаданных не вызывает часы и не изменяет PDF/filename/SHA/size/addedAt, текст страниц, подтверждения или исторические партии знаков.
- Update сначала валидирует вход, затем ищет документ; корректный неизвестный id возвращает null, некорректные метаданные вызывают прежнюю ошибку. Проверка ссылок из sign_catalog_batches вызывается только при смене kind и предшествует проверке amendsId. Любая историческая партия блокирует смену вида; изменение остальных реквизитов остаётся допустимым.
- Порядок отказов amendsId сохранён: self → missing base → изменение вместо основного документа → наличие собственных изменений. Явное отсоединение и привязка к другому основному документу остаются возможными. Перенос не вводит ограничение на одинаковый kind основного документа и изменения.
- Прежние SQL и сообщения ошибок сохранены; DocumentInUse перенесён в documents/errors с тем же конструктором, name и экспортом из store. Ошибки SQLite и часов не заменяются общим сообщением.

## Границы хранения и транзакций

Repository получает существующее соединение и часы; не открывает/закрывает SQLite, не мигрирует, не заполняет справочники и не создаёт backup. Сервис получает узкие операции repository и countSignBatches. Этот запрос пока собирается фасадом из прежнего SQL на том же соединении; при переносе каталога знаков его заменит соответствующий владелец хранения. Сервис не импортирует RegistryStore, DatabaseSync или HTTP.

Add/update сохраняют прежние одиночные SQL-записи без новой явной транзакции вокруг read-check-write. SQLite откатывает отклонённый trigger-ом INSERT/UPDATE; внешняя транзакция остаётся у вызывающего кода. Сервис не начинает и не завершает её. Этот структурный шаг не усиливает конкурентные гарантии старого сценария незаметно.

`document-web-import.ts` получает узкие list/add/backup, preview — только list. Тела расчёта эффекта, preview/fingerprint и apply не меняются: первоначальный план → backup → повторный план → add. Ошибка копии и устаревший план не записывают новый PDF; общий HTTP-контракт остаётся прежним.

Удаление документа пока находится в RegistryStore. [Текст страниц и подтверждения](document-evidence.md) теперь имеют отдельных владельцев; их прежние SQL/транзакции сохранены. Далее выделяется межмодульный сценарий удаления по [серверному плану](server-god-object-plan.md).

## Проверки и продолжение

Три [контракта фасада](../../server/__tests__/normative-document-contracts.test.ts) сначала прошли на исходном коде: нормализация/поля/receiver часов, порядок отказов и single-statement rollback. Восемь [прямых SQLite/service проверок](../../server/__tests__/normative-document-repository.test.ts) без RegistryStore проверяют read-only/порядок/whitelist/PDF bytes, повторное открытие и другое соединение, узкий запрос ссылок/ошибку, порядок часов, внешнюю транзакцию и блокировку записи, detach/reattach, сохранность текста/подтверждений/партий и узкий upload/backup port. Существующие документы/API/параметры, frozen JSON/SQLite и E2E сохраняются.

JSON v10/SQLite v13, нормативные правила, поля #110 и выпускной лист не меняются. Все PDF и данные тестов программно созданы и вымышлены. Текст страниц/подтверждения также выделены; далее удаление документа и каталог знаков. #135/А4 открыты; Pinia первой после А4, новые функции после всего технического этапа.
