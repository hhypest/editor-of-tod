# Атомарное удаление документа (#215 перед #135)

Это отдельное исправление поведения перед структурным выделением сценария удаления. На main `142e969` удаление `document_pages` и `normative_documents` выполнялось двумя независимыми записями. Отказ второго DELETE оставлял PDF и метаданные, но уже терял сохранённый текст. Регрессионная проверка с вымышленным PDF и BEFORE DELETE trigger предварительно воспроизвела дефект: вместо трёх прежних страниц получен null.

## Исправленная граница

`RegistryStore.deleteDocument` выполняет прежнее тело в существующем SqliteTransactionRunner.immediate. Одна BEGIN IMMEDIATE охватывает проверку существования, исторических партий знаков, прикреплённых изменений и подтверждений параметров, затем оба DELETE. Порядок проверок, SQL и DocumentInUse не меняются. До commit другое соединение видит прежний PDF/текст и не может записать новую ссылку между проверками и удалением.

Ошибка первой или второй записи откатывает весь сценарий, включая удалённый текст. Повтор после устранения причины возможен. Обычные HTTP 403/409/404/200 и общий ответ 500 сохранены; при 500 теперь сохраняются и страницы. Отсутствующий id по-прежнему возвращает false, но проверяется под той же блокировкой. Отказ BEGIN при занятой базе или вложенной транзакции не откатывает транзакцию вызывающего; удаление больше не выполняется внутри чужой транзакции неявно.

Используется прежнее соединение и существующий runner. Миграций, новых таблиц, форматов, автоматического backup или каскадного удаления истории нет. JSON v10/SQLite v13, нормативные алгоритмы, поля #110 и выпускной лист сохраняются.

## Проверки

[Семь проверок](../../server/__tests__/document-deletion.test.ts) покрывают отказ второго DELETE с восстановлением текста, отказ первой записи, прежний порядок исторических ссылок, блокировку до первого чтения, видимость старого текста между двумя DELETE, nested BEGIN/reopen и HTTP 403/500/409/200/404. Первая проверка сначала упала на исходном main и прошла после исправления. Данные и PDF тестов вымышлены; рабочие документы не используются.

Полные check, frozen JSON/SQLite, API и E2E дополняют эти проверки. Windows exe остаётся отдельной ручной контрольной точкой.
