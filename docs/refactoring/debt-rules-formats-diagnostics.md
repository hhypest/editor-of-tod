# Правила, исторические читатели и диагностика (#137)

Технический шаг после включённого #184 (PR #234, main a74e084). Новые функции 0.3.0 остаются после всей очереди; далее #138 и итоговая приёмка #191/main/Windows exe.

## Один источник порогов

`src/domain/regulation-thresholds.ts` вычисляет действующие минимумы пар ГОСТ/ОДМ из прежних `NormativeRules`: интенсивность для знаков, верхняя интенсивность и длина короткого участка. `rail-regulation`, `work-traffic`, подсказка, проверка условий и текст review используют одну проекцию.

Алгоритмы остаются различными: таблица Д.1 определяет знаки/регулирование/светофоры, а правило Б.33/Б.34 — число регулировщиков. Строгие и включительные сравнения, проверки неизвестных данных, тексты причин/предупреждений, нормативные параметры и подтверждения сохранены. Вынесение минимумов не создаёт нового нормативного значения и не меняет оснований (ГОСТ Р 58350-2019, Д.1; ОДМ 218.6.019-2016, пп. 6.4, 7.3.1, 13.7.5).

## Независимые читатели v2–v9

`src/domain/formats/frozen/` содержит копии прежних валидаторов и вложенных снимков ПУ-66/оснований v9, зафиксированные с a74e084. Общие подсхемы внутри этого исторического семейства допустимы: новые поля/форматы сюда не добавляются. Читатели не импортируют текущие `model`, `pu66-snapshot`, `decision-evidence-schema`, `title-block` или `post-distance`. Направление frozen → current domain запрещает архитектурный анализатор; негативный пример проверяет запрет.

`model.ts` сохраняет прежние публичные экспорты и миграции, но текущий v10 имеет собственные подсхемы. Читатель автономного v1 уже независим и остаётся в `legacy-v1.ts`. Алгоритмы миграций, JSON v10, SQLite v13 и белый список ПУ-66 не меняются. Порядок полей v10 сохранён: JSON-сериализация участвует в отпечатках ручных отметок. Старые фикстуры, SHA256SUMS, expected и review snapshots не обновляются.

Новая версия формата требует нового исторического снимка **до** изменения текущих схем. Исправление исторического читателя допустимо отдельным обоснованным изменением совместимости с проверками старых файлов; его нельзя автоматически обновлять вместе с текущей моделью.

## Состав диагностики при сборке

`scripts/diagnostic-files.ts` формирует отсортированный `src/shared/diagnostic-files.generated.ts` из исходников `src/`, `server/`, `scripts/`. Исключены тесты, декларации, скрытые каталоги, node_modules, неисполняемые файлы и символические ссылки. Корневые пользовательские каталоги не обходятся. Сохраняются `server.cjs` для SEA и исторический `server/store.ts` для уже записанных событий прежнего фасада.

Vite (build/dev/test) и упаковка exe обновляют файл до разрешения модулей. Проверенный файл хранится в Git для прямого запуска Node из исходников; `npm run check:diagnostics` выявляет рассинхронизацию до остальных проверок. После перемещения исходников обновите его командой `node scripts/diagnostic-files.ts`. Ручное перечисление файлов в runtime удалено; runtime не читает каталоги компьютера пользователя.

Прежний фильтр stack frames сохранён: только известный относительный файл, строка/столбец, максимум четыре кадра; имена функций, свободный текст, абсолютные корни и неизвестные пути отбрасываются. Существующий шаблон hashed browser index и формат диагностического отчёта v2 не меняются.

## Проверки

Семь предварительных сценариев порогов прошли **до** переноса; ранее также прошли 138 затронутых сценариев. После переноса проверяются прежние review-contract и frozen-formats, точные нижние/верхние границы при разных подтверждённых значениях ГОСТ/ОДМ, независимое чтение всех исторических JSON без текущих схем и отказы для новых вложенных полей/занятого next id. Проверки генератора фиксируют добавление/удаление файла, рассинхронизацию, приватные пути и symlinks; прежние client/server privacy-сценарии сохраняются.

Полный локальный check/E2E, тестирование состояния и Windows exe остаются после технического этапа по решению владельца. Целевые контракты этого переноса не заменяют итоговую регрессию.
