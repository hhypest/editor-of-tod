# Проекты и история: выделенный ProjectRepository (#135)

`server/projects/project-repository.ts` владеет SQL текущих проектов и неизменяемых редакций, преобразованием строк SQLite и операциями `list/get/listRevisions/getRevision/save/restore`. Это совместимый перенос по [ADR-0010](../adr/0010-modular-server-persistence.md). [Общий план](server-god-object-plan.md).

## Сохранённый контракт

- `save` проверяет текущую схему и размер полного UTF-8 JSON **до** начала транзакции и dedup. Лимит 32 МБ нельзя обойти уменьшением SQLite-снимка до SHA-ссылки.
- В прежней `BEGIN IMMEDIATE` сначала проверяется `expectedRevision`, затем возможность no-op. Совпадение содержимого не разрешает запись с устаревшей версией. No-op сохраняет номер/дату и не читает часы.
- Source, текущий draft и новая историческая редакция записываются атомарно. Отказ source/истории откатывает операцию; соединение пригодно для повторной попытки.
- `forceRevision` и `restore` создают новую редакцию даже при одинаковом содержимом. Отсутствующая исходная редакция возвращает `null`; устаревший ожидаемый номер даёт прежний конфликт.
- Чтение прежних снимков возвращает текущий `Scheme` и фактический `storedSchemaVersion`, не переписывая SQLite. Явное сохранение старого снимка пишет новую редакцию текущего формата; история остаётся прежней.
- Список проектов использует только последние краткие текстовые поля, ограничивает каждое 500 символами, заменяет значения другого типа пустой строкой, сортирует по дате и id. Полный исходник в список не попадает.

Репозиторий получает существующее соединение, узкие `encode/decode` [ProjectSourceStore](project-source-store.md) и функцию времени. Он не открывает/закрывает базу, не мигрирует её, не наполняет нормативный реестр и не знает HTTP/Vue. Транзакции проектных команд принадлежат репозиторию; модуль source участвует в них на том же соединении.

RegistryStore временно делегирует шесть прежних публичных методов. Часы передаются замыканием, сохраняющим прежний receiver фасада. Общие `RevisionConflict`/`ProjectTooLarge` вынесены в `server/storage-errors.ts`, а старые экспорты фасада указывают на **те же конструкторы**: HTTP mapper и существующие вызывающие сохраняют `instanceof` и сообщения. Цикла repository → facade нет.

## Проверки и следующий шаг

[Два контракта фасада](../../server/__tests__/project-repository-contracts.test.ts) сначала прошли до переноса: receiver/no-op/restore часов и rollback правки/new source при отказе записи истории.

[Прямые проверки](../../server/__tests__/project-repository.test.ts) используют SQLite без RegistryStore: no-op/force/restore, два соединения и конфликт, frozen inline v6 и сохранность байтов истории, ограниченный список, отказ source, повреждённый checksum и реальный большой UTF-8 проект. Сохраняются прежние store/API, frozen JSON/SQLite, source/recovery и браузерные проверки. JSON v10, SQLite v13, SQL, ошибки, нормативные алгоритмы и лист не меняются.

Восстановление затем выделено в [RecoveryRepository](recovery-repository.md), ручные реестры — в [LegacyRegistryRepository](legacy-registry-repository.md). Далее — ПУ-66 и остальные области хранения/маршруты. #135/А4 остаются открытыми; Pinia #191 идёт первой после А4, весь технический этап — до новых функций 0.3.0.
