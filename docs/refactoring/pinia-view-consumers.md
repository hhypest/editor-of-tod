# Представления читают Pinia, корень предоставляет команды (#191)

После включения #232 в main (8e8cb52) все владельцы из карты общего состояния уже реализованы: normativeRules, pu66Status, projectDocument, projectSessionUi, editorNavigation и catalogRefresh. Следующий шаг завершает переход основных потребителей с прежних session/props на эти stores.

## Представления и команды

`ProjectHub`, `RegistryHub`, `EditorWorkspace` и корневые status/preview bindings читают существующие данные через `storeToRefs`. Дополнительные refs-копии и watch-синхронизация не вводятся. Снята передача общих data props из App к этим трём представлениям.

- `ProjectHub` читает документ/ошибку/loading/dirty, копии восстановления/busy/refresh и выбранную вкладку из stores. Props содержат только шесть команд корневой сессии и локальные setup status/error.
- `EditorWorkspace` читает документ/историю/неприменённый ввод, template/PNG feedback, навигацию и версии каталогов из stores. Props содержат десять команд корня. Прежние dirty/draft/select события форм пишут в те же refs; применение правок выполняет прежняя команда.
- `RegistryHub` читает документ/блокировки, навигацию и счётчики каталогов из stores, без data props. Производные scheme/referencedSignIds вычисляются из того же документа; событие обновления каталога по-прежнему обрабатывает корень.

`src/composables/project-view-commands.ts` содержит только узкие типы Pick от прежнего ProjectSession, без runtime-операций. App один раз собирает стабильные объекты команд из методов единственной сессии. Корневой useProjectSession и все его 44 публичных ключа сохранены; deprecated aliases не удаляются. Компоненты не вызывают useProjectSession/useProjectRecovery/useEditorNavigation и не создают HTTP/recovery/lifecycle.

## Что сохраняется локально

Setup status/open/error и его startup/request lifecycle остаются у корня согласно [обоснованию #232](editor-navigation-store.md). Дочерние формы и переиспользуемые компоненты продолжают принимать узкие domain/feedback props и выдавать прежние события. Их ввод не превращается в ещё одну глобальную копию: pending refs служат прежней recovery-проекцией. DOM фокус/прокрутка, очереди, guards и browser lifecycle также остаются у прежних владельцев.

Не меняются сценарии открытия/сохранения/восстановления, JSON v10/SQLite v13, нормативы, поля #110, печать/PNG, зависимости и настройка CI. Переход меняет источник чтения общих данных и границу команд, без изменения экранов и подписей.

## Подготовленные сценарии и статус

`store-consumers.test.ts` монтирует настоящие SFC представлений через Vue renderer, подменяя только дочерние формы/каталоги. Подготовлены четыре сценария: live project/navigation/locks и делегирование create; два app с одним project id после смены active Pinia; сохранение shallow draft identity/dirty и делегирование apply; общие registry refresh/locks/referenced signs/diagnostics. Дополнительно проверяется, что чтение представления не вызывает корневую сессию, recovery repository или fetch. Это проверка границы компонентов, а не замена настоящих workflow/E2E контрактов.

Тесты в данном шаге **не запускались**. По решению владельца финальный check, тестирование состояния, E2E/регрессия и Windows exe выполняются после полного погашения технического долга. Статическая проверка типов/оформления при подготовке кода не означает итоговую приёмку. #191 остаётся открытой до включения этого шага; готовность реализации и результаты отложенных прогонов учитываются раздельно.
