# Архитектура и границы платформы

Документ описывает текущее устройство приложения и направление развития. На 30 сентября 2026 года реализованы работа одного составителя на своём компьютере: создание и импорт проекта, условная сборка Б.33/Б.34, лист A4 в SVG с выпускным режимом и PNG, локальные SQLite-реестры ПУ-66, знаков и нормативных документов, нормативные параметры с подтверждением. Согласование и совместная работа остаются следующими этапами.

## Исходная идея

Схема — самостоятельный версионируемый документ. Её данные состоят из параметров места работ, выбранного шаблона, размещённых объектов, реквизитов листа и сведений об источниках. В будущем геометрия печатного листа и PDF должны выводиться из этой модели; состояние интерфейса (выделенный объект, открытая вкладка, масштаб просмотра) хранится отдельно. Такой подход позволит одинаково проверять интерактивный лист, сохранённый JSON и печатный результат.

| Область             | Ответственность                                                | Появление  |
| ------------------- | -------------------------------------------------------------- | ---------- |
| Предметная модель   | Единицы измерения, данные схемы, версия JSON, инварианты       | Этап 1     |
| Нормативные профили | Документы по редакциям, параметры с подтверждением по цитате   | Этапы 1, 4 |
| Каталоги            | Переезды, знаки, происхождение и дата актуальности данных      | Этапы 1–2  |
| Редактор            | Состояние UI, команды, выделение, перетаскивание, отмена       | Этап 2     |
| Представление листа | SVG-лист A4, выпускной режим, печать, PNG; эталонные сравнения | Этап 2     |
| Согласование        | Редакции, замечания, роли, статусы и аудит                     | Этап 3     |

Модули внедряются по мере необходимости. Текущий процесс Node.js обслуживает локальный интерфейс и SQLite только на `127.0.0.1`; это не сервер совместной работы. Отдельный сервер для организаций и механизм входа выбираются лишь после описания участников, состава данных, режима доступа и требований к хранению.

## Данные схемы

Формат хранения должен явно включать `schemaVersion`, идентификатор и дату версии нормативного профиля, выбранный шаблон, измеренные параметры, реквизиты и список объектов. У справочной записи переезда должны быть источник, дата сверки и отдельный идентификатор; копия значимых исходных значений сохраняется в редакции схемы, чтобы обновление каталога не переписало исторический документ. Текстовые подписи и реальные размеры хранятся отдельно. Команды редактора работают с моделью, а генератор листа получает неизменяемый снимок редакции.

Старый проект из HTML использует `v: 1`, условные координаты и признаки `auto`. Импорт переводит v1–v6 через последовательные миграции в текущий `schemaVersion: 7`; исходный v1 JSON остаётся в поле `source.originalJson`. Новый проект создаётся только из карточки локального реестра ПУ-66 (`createSchemeFromPu66`; без карточки функция отклоняет создание, а сессия не открывает такой проект как новый), закрепляет ограниченный снимок выбранной редакции, содержит измерения только выбранного варианта и может собрать черновые объекты после выбора условий. К импортированному проекту и к проектам, созданным до 30.09.2026 с ручным идентификатором, составитель может отдельно закрепить карточку после сравнения; её дальнейшее изменение не переписывает схему. Изменения параметров и объектов применяются к снимкам v7; значения расстояний и скоростей по умолчанию считает `normative-defaults.ts` из нормативных параметров и не хранит отметку «по нормативу»; история отмены и повтора хранится только в памяти браузера. Ею и локальным сохранением управляет `useProjectSession`, а `App.vue` оставляет навигацию и локальные реестры. Явное сохранение создаёт новую редакцию SQLite; исходный JSON в новых снимках хранится по ссылке на общий хеш, при чтении собирается самодостаточная схема. Старые снимки не переписываются. Восстановление старой редакции создаёт новую без изменения прежней. Номер ожидаемой редакции защищает от перезаписи изменений другой вкладки. SQLite v8 хранит рабочие копии с неприменённым вводом отдельно от редакций и проверяет номер записи каждой копии; восстановление требует явного выбора и не меняет сохранённую редакцию. Скачивание JSON не подтверждает запись файла браузером и не удаляет recovery: состояние несохранённой работы зависит от записи в SQLite. PNG имеют ETag содержимого и требуют сверки после восстановления базы; адреса обновлены для обхода прежнего годового кэша. Переносной exe сравнивает хеш канонического пути базы с запущенным экземпляром и при отличии выбирает свободный порт. Рабочая область использует условные координаты и исходные локальные PNG для знаков; она не является печатным листом. Дальнейшие проверки и печатный лист описаны в [контракте формата](scheme-format.md).

Локальные реестры разделены на карточки ПУ-66, краткие записи о нормативных пунктах, каталог знаков, библиотеку нормативных документов и журнал подтверждений нормативных параметров; черновики схем хранятся отдельно в той же базе (SQLite версии 11).

- **ПУ-66.** Импорт хранит исходный XLSX вместе с извлечёнными строками и источником каждой редакции. В браузере он идёт через локальный API в два шага: просмотр без записи и подтверждение с повторной проверкой реестра и резервной копией; CLI использует тот же парсер. Выборка `/api/pu66/{ключ}/scheme` возвращает поля для снимка схемы, выборка `/norms` — интенсивность, категорию дороги, видимость и техническую таблицу только для подсказок в локальном редакторе; в проект и на лист она не попадает.
- **Нормативные документы.** PDF стандартов и методик хранятся по редакциям с датой введения и отметкой изменений; статус «действует/заменён» вычисляется по датам (`src/domain/normative-documents.ts`). Текст PDF извлекается pdf.js на сервере (`server/pdf-text.ts`) один раз и хранится постранично (`document_pages`).
- **Нормативные параметры.** Список чисел, которыми пользуются расчёты, с документом и пунктом задан в `src/domain/normative-parameters.ts`. Сервер находит пункт в тексте действующей редакции (`src/domain/document-text.ts`), составитель подтверждает значение; подтверждение с цитатой добавляется в журнал `parameter_confirmations`. Клиент получает состояние параметров и строит из него правила (`useNormativeRules`); подсказка способа пропуска, сборка шаблона, ступени скорости и значения по умолчанию расстояний и скоростей (`normative-defaults.ts`) берут значения оттуда. Схема пока не хранит, по каким подтверждённым значениям она собрана (шаг П3 дорожной карты).
- **Знаки.** Каталог извлекается из таблиц приложения А PDF ГОСТ Р 52290 (`server/sign-pdf.ts`) или загружается из ZIP; каждая загрузка создаёт партию с источником, изображения хранят историю редакций, проект может закрепить редакции использованных кодов.

Исходные PDF, их текст, изображения знаков и рабочие карточки хранятся только в локальной базе и в публичный код не включаются. Тесты используют программно собранные вымышленные PDF и книги.

## Сборка и запуск

`npm run dev` запускает Vite и локальный API, `npm run local` — собранное приложение. `npm run build:exe` собирает переносной исполняемый файл (Node.js SEA): сервер и зависимости упаковываются esbuild в один файл, интерфейс встраивается как ресурсы; pdf.js загружается только при разборе PDF и не требует модуля отрисовки.

## Согласование

Возможная последовательность состояний: черновик → внутренняя проверка → направлено участникам → замечания или согласовано → финальная редакция → архив. Это модель для уточнения с пользователями, а не утверждение обязательного юридического маршрута. Каждое направление связывается с конкретным неизменяемым PDF и его редакцией; новая правка создаёт новую редакцию. Статус, время, автор и способ подтверждения фиксируются отдельно от изображения подписи на листе.

## Проверяемость

Для каждого правила хранятся ссылка на источник и результат предметной проверки. Тесты охватывают валидаторы, вычисления и миграции; визуальные примеры проверяют печатный лист. Версия исходных данных сохраняется рядом с экспортом. Перед применением пользователь сверяет схему с фактической геометрией дороги, видимостью, существующими знаками и условиями работ.
