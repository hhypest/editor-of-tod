# Перенос автономного редактора

Источник анализа — предоставленный файл `Схемы_ОДД_переезды.html` и руководство пользователя от сентября 2026 года. Исходник представляет собой один автономный HTML-файл с CSS, JavaScript, SVG и встроенными данными; в репозиторий он не загружен. Таблица описывает **наблюдаемое в прототипе**, а не выполненную миграцию.

| Возможность прототипа | Данные и поведение                                                                            | Направление переноса                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Два варианта          | Б.33 и Б.34, автоматическая расстановка, параметры скоростей и длин                           | Отделить правила от геометрии; сверить условия выбора с источниками                                     |
| Реестр переездов      | 73 записи из ПУ-66 внутри `DATA.reg`                                                          | Источник с владельцем, датой сверки и правом использования; в открытом коде только обезличенные примеры |
| Каталог знаков        | 420 изображений внутри `DATA.signs`                                                           | Сделано: локальный каталог из PDF ГОСТ Р 52290 или ZIP с историей редакций                              |
| SVG-лист              | Привязка объектов к зонам, ручное перемещение, условный масштаб                               | Модель в физических единицах и независимый слой отображения                                             |
| Проект                | JSON с `v: 1`, `params`, `head`, `objects`, `nid`                                             | Схема нового формата и проверяемый односторонний импорт                                                 |
| Сохранение            | Один автосохранённый проект в `localStorage` под ключом `odd_scheme_v1`; отдельные JSON-файлы | Несколько проектов, версия и явная стратегия восстановления                                             |
| История               | До 60 снимков для отмены, без повтора                                                         | Команды или снимки с отменой и повтором; проверка сохранности ручных правок                             |
| Вывод                 | Печать A4 landscape/PDF в браузере и PNG 3360×2376                                            | Сделано: SVG-лист, выпускной режим, PNG 3528×2495; визуальные эталоны ещё не собраны                    |

## Что проверить перед кодированием шаблонов

1. Пользователь подтвердил правило этого проекта: Б.34 для фронта менее 30 м, Б.33 — для 30 м и более. Размерная цепочка в предоставленном образце Б.34 ошибочна и не служит эталоном. Применимость остальных элементов шаблонов следует сверять с ОДМ и условиями работ.
2. Условный масштаб листа означает, что подписанные расстояния не равны длинам нарисованных отрезков. Программа не должна рассчитывать реальные расстояния по пикселям.
3. Смена варианта, скорости или жёлтого фона в прототипе перестраивает типовые объекты и может сбросить ручные сдвиги. При переносе нужны предсказуемое поведение, предупреждение и проверка отмены.
4. Исходный импорт проверяет лишь наличие `params` и `objects`. В новой версии необходима полноценная валидация типов, чисел, ссылок на знаки и длины текста перед отображением и печатью.
5. Подписи в шапке и примечаниях содержат конкретные должности и организацию. Сейчас реквизиты редактируются; по сообщённому порядку утверждает владелец дороги, согласовывает Госавтоинспекция. Профили организаций и маршрут передачи ещё не реализованы.
6. Встроенный каталог и реестр могут устаревать независимо от кода. Для каждой новой схемы фиксировать версию использованных данных.

## Текущее состояние импорта

Приложение принимает файлы `v: 1` до 10 МБ и `schemaVersion: 2/3/4/5` до 32 МБ. Оно проверяет известные поля, уникальность ID объектов, сохраняет их порядок и условные координаты, переводит числовые расстояния в метры и хранит точный исходный v1 JSON внутри проекта. Для повреждённого файла возвращается ошибка с путём поля. Редактирование и локальное сохранение работают в формате v5; старые редакции SQLite преобразуются при чтении без изменения прежних снимков. Новый проект без исходного JSON создаётся только по карточке из локального реестра ПУ-66 (поиск по км и пк, станции, участку, дороге); ручного ввода идентификатора нет. У импортированного v1 карточку составитель закрепляет явным действием после просмотра отличий; автоматического сопоставления по старому ключу нет. Выбор карточки не подтверждает её актуальность или применимость номеров знаков к схеме. Просмотр координат не заменяет сравнение печатных листов и предметную сверку.

## Критерий полной миграции старого JSON

Составить обезличенный набор реальных по структуре файлов `v: 1`: Б.33, Б.34, вручную перемещённые и добавленные объекты, изменённая шапка, неизвестный знак и отсутствующий переезд. Для каждого файла зафиксировать ожидаемый результат. Импорт не меняет исходный файл; пользователю показывается отчёт о преобразовании и возможность сохранить новый проект отдельным файлом. Сравнить листы до и после на A4, затем проверить ключевые расстояния и номера знаков вручную.

Дополнительные поля новых файлов v1 сохраняются в v5: `objects[].fz`, `params.n100/n50`, `front`, `reg`, `loc`, `size`, `vIn`, `locLast`, `zPu`. Неизвестные ключи перечисляются в отчёте импорта и остаются в исходном тексте. Вымышленный проверочный файл: `tests/fixtures/legacy-v1-new-fields.json`.
