# Запуск и сборка на разных платформах

[Каталог документации](README.md) · [Начало работы для составителя](getting-started.md) · [Разработка и команды](development.md)

Программа — локальный сервер Node.js и интерфейс в браузере. Она слушает только `127.0.0.1`, хранит данные в одном файле SQLite и не требует ни внешней базы, ни установки с правами администратора. В зависимостях нет модулей, которые нужно компилировать под платформу: SQLite встроен в Node.js. Поэтому из исходников программа запускается одинаково везде, где есть подходящий Node.js, а различия платформ сводятся к готовому исполняемому файлу.

## Что проверено

Поддерживаются Windows и Linux. Другие системы и запуск в контейнере не поддерживаются и не проверялись.

| Платформа         | Запуск из исходников | Готовый исполняемый файл                                   | Чем подтверждено                                                                                                    |
| ----------------- | -------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Windows 10/11 x64 | Да                   | Да — `editor-of-tod.exe`, основной способ для составителя  | CI: `npm run check` на Windows; ручной процесс «Windows exe» с браузерными сценариями; работа на рабочем месте      |
| Linux x64         | Да                   | Да — `editor-of-tod-linux-x64`, собирается на самой машине | CI: `npm run check` и браузерные сценарии на Ubuntu; файл собран и прошёл 43 браузерных сценария вручную 06.10.2026 |
| Docker            | Не поддерживается    | —                                                          | См. раздел «Docker»                                                                                                 |

«Проверено» означает запуск программы и автоматические сценарии. Предметную приёмку листов составитель проводил только на Windows.

## Общие требования

- Node.js 24 от 24.12.0 либо Node.js 26 от 26.7.0 (`engines` в `package.json`; обычная версия — в `.nvmrc`), npm и Git — для запуска из исходников и для сборки. Готовому исполняемому файлу Node.js не нужен.
- Современный браузер на основе Chromium (Edge, Chrome). Автоматические сценарии выполняются в Chromium; другие браузеры не проверялись.
- Папка, доступная для записи: в ней создаётся `private-data` с базой и резервными копиями.

## Запуск из исходников (любая платформа)

```bash
git clone https://github.com/hhypest/editor-of-tod.git
cd editor-of-tod
npm ci
```

Дальше — один из трёх режимов.

| Режим                | Команды                                  | Адрес                    | Для чего                                                                                                       |
| -------------------- | ---------------------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Разработка           | `npm run dev`                            | `http://127.0.0.1:5173/` | Правка кода: интерфейс Vite с обновлением на лету и локальный API на порту 4100                                |
| Собранная версия     | `npm run build`, затем `npm run local`   | `http://127.0.0.1:4100/` | Работа без exe на Linux: тот же интерфейс и API, браузер открываете сами                                       |
| Как исполняемый файл | `npm run build`, затем `npm run desktop` | адрес в терминале        | Проверка точки входа exe: подбор порта, открытие браузера, повторный запуск открывает уже работающую программу |

В первых двух режимах база по умолчанию — `private-data/registry.sqlite` в папке репозитория. В режиме `desktop` папка данных выбирается относительно исполняемого файла Node.js, поэтому путь к базе лучше задать явно переменной `TOD_DATABASE_PATH`.

Переменные окружения задаются по-разному:

```bash
# Linux
TOD_DATABASE_PATH="$HOME/tod-data/registry.sqlite" npm run desktop
```

```powershell
# Windows PowerShell
$env:TOD_DATABASE_PATH = "D:\tod-data\registry.sqlite"; npm run desktop
```

```bat
:: Windows cmd
set TOD_DATABASE_PATH=D:\tod-data\registry.sqlite
npm run desktop
```

Полный список переменных (`TOD_PORT`, `TOD_NO_BROWSER`, `TOD_E2E_EXE`) — в [руководстве разработчика](development.md).

## Windows

**Запуск.** Составитель получает `editor-of-tod.exe` и три файла лицензий, кладёт их в папку с правом записи и запускает двойным щелчком. Порядок работы, обновления и резервных копий — в [руководстве составителя](getting-started.md). Файл не подписан: SmartScreen или политика организации могут потребовать подтверждения.

**Сборка.**

```bash
npm ci
npm run build:exe
```

Результат — `release/editor-of-tod.exe` и файлы `LICENSE.txt`, `LICENSE.ru.txt`, `THIRD_PARTY_LICENSES.txt`; в конце печатается SHA-256 файла. Передавайте все четыре файла вместе.

- Цель сборки — только Windows x64. Сборка для Windows на ARM не предусмотрена и не проверялась.
- Собрать `editor-of-tod.exe` можно и на Linux той же командой: скрипт сам скачивает `node.exe` той же версии, что установленный Node.js (нужен доступ к реестру npm). Проверено 06.10.2026; в CI файл собирается на Windows.
- В GitHub файл собирает процесс «Windows exe» (`.github/workflows/windows-exe.yml`). Он запускается только вручную, проверяет готовый exe браузерными сценариями и сохраняет файлы как артефакт запуска на 14 дней. Автоматической публикации нет.
- Предупреждение `warning: The signature seems corrupted!` при сборке ожидаемо: в копию `node.exe` внедряются данные программы, и её прежняя подпись перестаёт действовать.
- Контрольная сумма зависит от версии Node.js и системы, на которой шла сборка, поэтому у файлов, собранных на разных машинах, она разная. Сверяйте сумму с той, что напечатана в журнале именно вашей сборки.

**Проверка готового файла** браузерными сценариями:

```powershell
$env:TOD_E2E_EXE = "release\editor-of-tod.exe"; npm run test:e2e
```

## Linux

**Запуск без сборки файла** — режим «Собранная версия» из таблицы выше: `npm run build`, `npm run local`, открыть `http://127.0.0.1:4100/`.

**Сборка исполняемого файла** для той же системы и архитектуры, на которой идёт сборка:

```bash
npm ci
npm run build-only
npm run package:exe -- --target host
```

Результат — `release/editor-of-tod-linux-x64` (на ARM — `…-linux-arm64`) и те же три файла лицензий. Запуск:

```bash
./editor-of-tod-linux-x64
```

- Программу запускают из терминала и оставляют его открытым: в нём показаны адрес и путь к базе, закрытие останавливает программу.
- Браузер открывается командой `xdg-open`. Если её нет или нет графической среды, откройте адрес из терминала вручную либо запускайте с `--no-browser`.
- Данные создаются в `private-data` рядом с файлом. Если туда нельзя писать, используется `$XDG_DATA_HOME/editor-of-tod/private-data`, а без этой переменной — `~/.local/share/editor-of-tod/private-data`.
- Файл содержит тот Node.js, которым его собирали, и требует на целевой машине совместимой системной библиотеки (glibc). Собирайте на той же или более старой системе, чем та, где программа будет работать. Запуск на дистрибутивах с musl (Alpine) не проверялся.
- Предупреждения `Can't find string offset for section name '.note.100'` при сборке не мешают работе файла.
- Готовый файл для Linux в CI не собирается и не распространяется: его собирают на месте.

**Проверка готового файла:**

```bash
TOD_E2E_EXE=release/editor-of-tod-linux-x64 npm run test:e2e
```

Перед браузерными сценариями установите Chromium: `npx playwright install --with-deps chromium`.

## Docker

Контейнер для этой программы не нужен и не поддерживается; готового образа и `Dockerfile` в репозитории нет.

- **Назначение.** Программа рассчитана на одного составителя на его компьютере. Запуск уже сводится к одному файлу или к `npm ci` и одной команде; ни внешней базы, ни дополнительных служб нет — контейнер ничего не упрощает.
- **Сеть.** Сервер слушает только `127.0.0.1` и не имеет входа по паролю. Проброс порта из контейнера (`-p 4100:4100`) с таким адресом не работает, а открытие сервера на все адреса сделало бы незащищённый API с карточками ПУ-66 доступным по сети. Менять это ради контейнера нельзя.
- **Данные.** База, копии и исходные книги ПУ-66 конфиденциальны и лежат в `private-data`. В контейнере их пришлось бы выносить в том; при ошибке в настройке данные остаются внутри контейнера и теряются при его удалении.
- **Браузер и печать** всё равно работают на самом компьютере, вне контейнера.

Единственный разумный случай — воспроизводимая среда для проверок кода на Linux (образ с Node.js 24, каталог репозитория подключён томом, `npm ci` и `npm run check`). Это среда разработки, а не способ работы с программой; такой запуск в проекте не настроен и не проверялся.

Если программа когда-нибудь станет сервером для нескольких пользователей, вопрос о контейнере решается заново — вместе с входом, ролями и хранением данных (этап 3 [дорожной карты](../ROADMAP.md), [ADR-0001](adr/0001-local-application.md)).

## Перенос данных между платформами

База — один файл `registry.sqlite`, его формат от платформы не зависит. Чтобы перенести работу, остановите программу, скопируйте папку `private-data` целиком (с `backups`) и на новом месте положите её рядом с исполняемым файлом либо укажите путь в `TOD_DATABASE_PATH`. Файлы `registry.sqlite.instance.json` и `registry.sqlite.launch.lock`, если они остались после аварийного завершения, переносить не нужно. Перенос с Windows на Linux на рабочих данных не проверялся; сначала проверьте его на копии. Данные остаются конфиденциальными на любой платформе: [реестр ПУ-66](pu66-data.md).
