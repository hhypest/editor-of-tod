# Совместимость форматов и результатов

Тип: действующая справка; актуальная реализация и ограничения.

Действующая карта для разработчика, сверена 02.11.2026 по main 22c08f8 и срезу ручного размещения v13. Полный контракт полей — [формат проекта](../scheme-format.md), происхождение прежних контрактов — [архив первого блока](../archive/refactoring/first-block-contracts.md). Текущая очередь находится в [ROADMAP](../../ROADMAP.md).

Для старых проектов с активными примыканиями/tee действует [сохранная граница первого #107](../verification/reports/2026-11-01-prototype-comparison.md): связанные объекты ручные, исходник точный; до поддержки геометрии общая перестройка и выпуск закрыты. Старые v11 защищены по originalJson без молчаливого переписывания placements. Сохранение/экспорт доступны, embedded ПУ-66 не привязывается автоматически.

## Проект и исторические читатели

Текущий экспорт — JSON v13, SQLite — v13. [model.ts](../../src/domain/model.ts) сохраняет публичные экспорты и миграции. Автономный `v: 1` читается независимо в [legacy-v1.ts](../../src/domain/legacy-v1.ts); читатели schemaVersion 2–12 зафиксированы в [formats/frozen/](../../src/domain/formats/frozen). Они не импортируют текущие model, pu66-snapshot, decision-evidence-schema, title-block или post-distance. Общие подсхемы внутри исторического семейства допустимы, новые поля текущего формата туда автоматически не добавляются.

Модель примыканий v12 и её границы описаны в [ADR-0012](../adr/0012-road-layout-model.md). Узлы и исторические связи сохраняются отдельно; установка стойки не вычисляется из координат. Непустая модель закрывает перестройку/выпуск до готовности геометрии, включая проекты без legacy source.

Перед следующей версией формата нужно зафиксировать прежний текущий читатель. Изменение исторического валидатора требует отдельного объяснения совместимости и проверок прежних файлов; обновление текущей подсхемы не должно расширять исторический формат. Порядок свойств важен там, где JSON-сериализация участвует в отпечатках и планах.

Чтение старой редакции преобразует Scheme в памяти и возвращает storedSchemaVersion. Снимки SQLite не переписываются; явное сохранение создаёт новую редакцию. Импортированный v1 сохраняет полный source.originalJson; внутренний dedup SQLite не делает внешний экспорт неполным. Прежний снимок ПУ-66 не дополняется новыми полями автоматически — расширение выбирают явно после сравнения. Детали записи и source-проверок — [сервер и хранение](server-and-storage.md).

Новый вариант рабочей формы `kind: road-node` хранится в существующей `placement_json`, без изменения таблиц. Старые формы sign-post/element читаются как прежде; старый выпуск программы не распознаёт новую форму восстановления, хотя применённый JSON v12 сохраняет прежний контракт. Сверять рабочую копию следует текущей программой. Удаление связанного узла пока отклоняется до сохранения отсоединённых правок РП4; узлы без связей удаляются с общей отменой.

## Review, отметки и рисунок

При структурном переносе сохраняются коды, порядок, kind, текст и основания находок; действующие отметки «Проверено» и их инвалидация; предметная проекция листа и результат drawSheet. [Review contract](../../src/domain/__tests__/review-contract.test.ts) и [review marks](../../src/domain/__tests__/review-marks.test.ts) защищают эти границы. Снятые до переноса golden snapshots и SHA рисунков не обновляют для сокрытия расхождения. Обоснованное предметное изменение может изменить эталон отдельным проверяемым решением; архив сохраняет причины таких прежних изменений.

Golden фиксирует вывод кода на вымышленных образцах. Он не удостоверяет нормативную правильность и не заменяет просмотр браузерного SVG, PNG и печати A4. Подписи, метры, координаты листа и реальные расстояния остаются разными сущностями. Для стоек с distance используется шкала [post-distance](../../src/domain/post-distance.ts), лист остаётся без равномерного масштаба. Исходный снимок и рисунок старого проекта не исправляются молча при открытии.

Общая [проекция порогов регулирования](../../src/domain/regulation-thresholds.ts) используется проверками и подсказкой, но алгоритмы сохраняют разные задачи: таблица Д.1 определяет способ пропуска, Б.33/Б.34 — число регулировщиков. Общие минимумы не вводят новое нормативное правило. Строгие/включительные границы, неизвестные данные и основания сохраняются; ссылки на источники — в [нормативной модели](../standards.md).

Команды и способ фиксации результата описаны в [методике](testing.md); действующие ручные сценарии доступны через [TESTING.MD](../../TESTING.MD). Факт проверки конкретной сборки записывается отдельным протоколом, а не заменяется текущим числом тестов в этой карте.

Условный рисунок примыканий использует существующий v12 sheetOffsetXSvg и не меняет геометрию стоек/таблички при чтении. RoadNodeDraft получил необязательную строку sheetOffsetXSvg: старый recovery без строки сохраняет применённый отступ, пустая строка явно сбрасывает его в null. Сохранённый ноль читается как ноль. Старые sign-post/element формы, версии JSON/SQLite, frozen-читатели и эталоны неизменны. Общая перестройка и выпуск П6 остаются под защитой.

Чтение рабочих форм совместимо назад: программа до добавления поля отступа может не распознать новую неприменённую форму с sheetOffsetXSvg. Применённые проекты v12 при этом сохраняют совместимость.

Ручная форма связи стойки добавляет необязательный roadLink только в draft sign-post. Старые формы без этого поля читаются с сохранением links/installation и происхождения; старое приложение может не прочитать новый неприменённый ввод. Этот срез использовал v12 без новых persisted fields/таблиц; ноль установки и неизвестный null не смешиваются.

Ручное размещение на ветви — JSON v13 / SQLite v13, [ADR-0013](../adr/0013-branch-post-placement.md). Независимый читатель v12 зафиксирован вместе с road-layout-v12; миграция меняет только envelope и не создаёт branchPlacement. Новое необязательное поле хранит выбранную ветвь, условные along/across и поворот четвертями. Основное положение/расстояние сохраняется неактивным; явное снятие размещения восстанавливает его. Старые неприменённые формы без branchPlacement сохраняют применённое размещение; явное enabled: false снимает его. Прежняя программа не обязана читать v13 или новый ввод; историю SQLite не переписывают при открытии. Frozen v13 добавлен отдельно, старые fixture/контрольные суммы/предметные ожидания сохранены. Общая защита П6 не снята.
