# Сервер, хранение и атомарные операции

Тип: действующая справка; актуальная реализация и ограничения.

Действующая карта для разработчика. Сверено 29.10.2026 по реализации main a5ad72f; документальная основа — 4f3acd6. Серверный А4 принят 27.10.2026. Обоснование — [ADR-0010](../adr/0010-modular-server-persistence.md), общие границы — [архитектура](architecture.md).

## Сборка и соединение

[createServerServices](../../server/composition-root.ts) открывает одно соединение SQLite, выполняет migration/backup, создаёт владельцев проектов/recovery/реестров, ПУ-66, знаков и документов, затем наполняет пустой ручной нормативный реестр. Все repositories и TransactionRunner получают это же соединение. Общие ProjectSourceStore и Pu66KeyResolver создаются один раз.

При отказе инициализации root выполняет best-effort rollback/close и возвращает исходную ошибку. После успеха соединение принадлежит вызывающему. [ServerRuntime](../../server/server-runtime.ts) связывает узкие HTTP/CLI-порты с сервисами, предоставляет metadata, backup и close. Это сборка приложения; маршруты не получают полный объект сервисов или DatabaseSync. RegistryStore и совместимый серверный фасад удалены.

[HTTP server](../../server/http/server.ts) сохраняет security, порядок групп, контекст нормативного запроса, finish-диагностику, error mapper и static/fallback. Несовпавший RouteHandler возвращает false без чтения тела и отправки ответа. Host/Origin, лимиты JSON в байтах, однократное декодирование ключей, PDF/PNG и ETag принадлежат [транспорту](../../server/http); SQL и атомарные команды — владельцам хранения. API, desktop и CLI используют общий runtime, а не собственные варианты сборки. Начальные записи seed сохраняются по одной: отказ второй не откатывает уже сохранённую первую; непустой реестр не дополняется автоматически.

## Проекты, исходный JSON и recovery

ProjectRepository валидирует полную схему и размер UTF-8 JSON до транзакции и dedup. В `BEGIN IMMEDIATE` сначала проверяется expectedRevision, затем no-op. Совпадение содержимого не разрешает запись с устаревшей версией. No-op не создаёт редакцию и не читает часы; forceRevision и restore создают новую редакцию даже при совпадении содержимого. Source, draft и новая история фиксируются вместе либо откатываются вместе.

ProjectSourceStore сохраняет исходные байты legacy JSON по SHA-256. Decode проверяет форму ссылки, наличие исходника и хеш, возвращает самодостаточный Scheme; внутренний SHA не заменяет исходник во внешнем JSON. Cleanup проверяет ссылки текущих проектов, всех редакций и recovery; удаляется только последний неиспользуемый исходник. Store не открывает базу и не начинает транзакции.

Recovery.save под одной блокировкой проверяет активного владельца, восстанавливает полный Scheme, проверяет лимит 32 МБ с неприменённым вводом, затем owner/expectedVersion и пишет source/snapshot/lease. Повторное использование SHA разрешено только для исходника этой же копии. Чужой активный владелец отклоняется до разбора Scheme. Claim/delete также атомарны; renew/release — одиночные UPDATE без изменения снимка/версии. Удаление recovery и cleanup последней ссылки входят в одну транзакцию. Внешний лимит тела PUT проекта/recovery включает 32 МиБ + 64 КиБ транспортного запаса.

## ПУ-66 и повтор плана после backup

Текущий ключ карточки имеет приоритет над alias; неоднозначный alias отклоняется, цепочки автоматически не исправляются. Scheme/norms/list — разные проекции; утверждённый в v11 белый список снимка описан в [ПУ-66](../pu66-data.md). История карточки не переписывает снимки проектов.

Сверка проверяет вход и будущую местную дату до транзакции; внутри блокировки заново читает редакцию, проверяет expectedRevision и исключение, затем добавляет запись. История идёт по id DESC, текущая сверка — по фактической дате и id для текущей редакции; прежняя сверка не становится сверкой новой карточки.

Import/lifecycle сохраняют последовательность preview → backup → синхронная команда записи. После асинхронной копии весь план повторно проверяется внутри `BEGIN IMMEDIATE`. Изменение карточки, её статуса или истории преемника делает прежний fingerprint недействительным. Ошибка поздней записи откатывает весь пакет. Обычный импорт не возвращает исключённую карточку; возврат выбирается явно. Неизменённая книга не создаёт новую редакцию/время, но её карточку можно явно вернуть без изменения книги.

## Документы, знаки и транзакции

[DeleteNormativeDocument](../../server/documents/delete-normative-document.ts) в одной `BEGIN IMMEDIATE` проверяет существование, ссылки любых исторических партий знаков, прикреплённые изменения, подтверждения, затем удаляет страницы и PDF/метаданные. Сбой любого чтения/DELETE откатывает всё; новое подтверждение не может появиться между проверкой и удалением. Отказ вложенного BEGIN не откатывает транзакцию вызывающего: BEGIN расположен до try у [TransactionRunner](../../server/database/transaction-runner.ts).

Замена текста страниц также атомарна: до commit другое соединение читает прежний текст. Null cache отличается от сохранённого пустого результата извлечения; пустой скан не разбирается повторно. История подтверждений append-only, исторические ссылки учитывают все подтверждения. Смена kind документа блокируется ссылкой из любой партии знаков, включая неактивную.

Импорт каталога знаков фиксирует batch/current/history/active/retirement одной транзакцией. No-op не вызывает часы и запись. Relabel не переписывает историческую редакцию; возврат знака создаёт новую active-редакцию. Исторические PNG остаются доступны закреплённым проектам. Общая SQLite обеспечивает эти операции; репозитории сами по себе не становятся автономными базами или микросервисами.

## Миграции и проверки

Текущая SQLite v13. Новая база проходит 0 → 1 → 3 → … → 13; v2 — отдельная историческая ветка. Будущая версия отклоняется до копии/изменений. Поддерживаемая старая файловая база получает одну копию до первого шага; отказ копии блокирует обновление. Текущая база не получает повторную копию/DDL. Особая v2 очищает SVG с secure_delete и выполняет VACUUM вне транзакции; backup v2 не создаётся, версия 3 ставится только после успешной очистки. Неудачный VACUUM допускает повтор. Миграции не являются одной общей транзакцией: завершённые шаги сохраняются. [Migration runner](../../server/database/migration-runner.ts) не принимает чужую открытую транзакцию.
