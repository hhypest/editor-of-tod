## Уточнение #103 и реализация

- Пункт 8 ПУ-66 — полная длина ответственности за текущий ремонт автомобильной дороги в границах переезда, по половине в каждую сторону от оси. Он ограничивает только фронт работ; отгон и буфер в него не входят.
- По принятому решению текущий предел фронта — 45 м. Оба порога остаются параметрами `project-front-limit` и `project-b34-max-front`, с прежними основаниями ОДМ 218.6.019-2016, рис. Б.33/Б.34. Интерпретация п. 8 и исключение для частичного Б.34 — предметное решение владельца от 29.10.2026, а не новая цитата из ОДМ.
- «Взять фронт из п. 8 ПУ-66» задаёт полный сплошной фронт: до порога 30 м включительно — Б.34; свыше — Б.33. Отгон и буфер сохраняются.
- Для фронта свыше 30 м в пределах переезда есть отдельный явный переход на Б.34 с частичным фронтом и обратный переход на сплошной Б.33. Сплошной Б.34 при этой длине недоступен; запрет проверяется также вне формы, при построении и допуске к выпуску.
- При изменении размера автоматически выбирается вариант по порогу; переход на Б.33 задаёт сплошной фронт. Сохранённый длинный частичный Б.34 остаётся выбранным при правке других полей.
- Ручная правка длины снимает признак подстановки. Работа идёт с закреплённым снимком; обновление локальной карточки не переписывает проект.
- Прежний проект открывается как сохранён. При превышении общего предела дальнейшее применение правок и построение блокируются до исправления фронта; выпуск уже ограничен общей проверкой условий. Импорт, хранение и скачивание копии для сохранности не запрещаются.
- Явные переходы используют существующую общую историю и перестройку П5: одна отмена возвращает параметры и объекты. JSON остаётся v11, SQLite v13; новых зависимостей нет.

## Повторная проверка

Сценарии ниже перенесены из исходного TESTING.MD без изменения ожидаемого поведения. Перед проверкой укажите точный SHA и номер новой Windows exe, контрольную сумму и фактический результат. Принятие старой сборки и успешный CI не заменяют это решение. Базовые числа в примерах — 30/45 м; при иных подтверждённых параметрах границы пересчитываются.

1. На вымышленных карточках с п. 8 равным 24, 30, 38 и 45 м нажать «Взять фронт из п. 8 ПУ-66» при создании: 24/30 м — Б.34, 38/45 м — Б.33, во всех случаях сплошной фронт. Отгон и буфер не включаются в длину; размер не делится пополам. Половина относится к каждой стороне от оси.
2. Повторить подстановку в существующем проекте, в том числе при неизменённой длине частичного Б.34. После применения должен быть полный сплошной фронт и вариант по порогу.
3. На Б.33 с фронтом 38 м выбрать «Выбрать Б.34 с частичным фронтом». Проверить тот же размер, частичный вид, недоступность «Сплошной», отсутствие ложного замечания «Вариант и длина фронта». Изменить другое поле, применить, сохранить/открыть и скачать/импортировать JSON: частичный Б.34 сохраняется. Проверить рисунок, ручные объекты и режим пропуска.
4. Вернуться кнопкой «Выбрать Б.33 со сплошным фронтом». Одно «Отменить действие» возвращает частичный Б.34 вместе с объектами, повтор — сплошной Б.33. При неприменённом вводе обе кнопки недоступны.
5. Ввести 45,1 м (или больше действующего предела) при создании и правке: продолжить нельзя. Открыть прежний JSON с таким фронтом: размер не подменяется; применение других правок, построение и выпуск закрыты до исправления фронта. Скачивание копии для сохранности доступно.
6. Открыть прежний Б.34 со сплошным фронтом 38 м: импорт сохраняет значения, проверка блокирует построение/выпуск; явный переход по порогу исправляет вариант. Кнопкой проверки обходить запрет нельзя.
7. Изменить фронт вручную после подстановки: признак ПУ-66 снимается. Обновление карточки в реестре без явного обновления связи не меняет закреплённый предел и проект. На коротком п. 8 нельзя превысить его даже при общем пределе 45 м.
8. Сверить A4/PNG для 30 м сплошного Б.34, 38 м сплошного Б.33 и 38 м частичного Б.34: подписи, оба направления, места работ и отсутствие обрезки. Автотесты и первая приёмка не подменяют этот результат.
