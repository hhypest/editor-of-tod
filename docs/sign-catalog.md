# Локальный каталог дорожных знаков

## Знаки из PDF стандарта

Основной способ наполнить каталог — извлечь изображения из PDF ГОСТ Р 52290, прикреплённого в «Реестры» → «Нормативные документы» с назначением «Изображения знаков». В «Импорт Excel и знаков» выберите документ и нажмите «Извлечь знаки из PDF».

Как работает извлечение (`server/sign-pdf.ts`):

- Берутся растровые изображения между заголовком «Таблица А.1» и заголовком «Приложение Б» (изображения на масштабной сетке приложения Б не используются).
- Номер знака — ближайшая подпись вида `1.34.1` или `6.9.1 <*>` ниже изображения в той же колонке; если строка таблицы разорвана страницей, подпись ищется вверху следующей страницы.
- Поле вокруг знака становится прозрачным. Изображение, в котором несколько разновидностей разделены пустым полем (например, три длины знака 1.34.1), делится на части. Второе и следующие изображения одного номера получают коды `_v2`, `_v3` в порядке «сверху вниз, слева направо».
- Перечень знаков, которые допускается выполнять с жёлтым фоном, читается из текста стандарта (в ГОСТ Р 52290-2024 — п. 3.2) с диапазонами вида «3.18.1 - 3.25». Для них строится вариант `_ж`: белый фон внутри знака окрашивается в жёлтый, кайма и символы не меняются. Если перечень не найден, варианты `_ж` не создаются.
- Изображение с номером (`?numbered=1`) для знаков из PDF совпадает с изображением без номера.

Просмотр показывает страницы, число изображений и знаков, цитату пункта о жёлтом фоне и все изображения с найденными номерами. Отбор «Требуют проверки» оставляет изображения без номера, исправленные, варианты `_vN` и примеры знаков индивидуального проектирования. Номер можно исправить или снять отметку «в каталог»; после изменений нажмите «Проверить снова». Пока у изображения нет номера и оно не исключено, запись недоступна. Запись заменяет каталог целиком, создаёт резервную копию SQLite и указывает источником документ библиотеки (код, редакция, SHA-256 PDF).

Знаки 3.24 с другими значениями скорости и таблички 8.1.1 с другими расстояниями в стандарте не изображены: программа рисует их на листе сама, и при закреплении редакций PNG для них не требуются. Коды из прежнего ZIP, которых нет в PDF, исключаются из текущего каталога, но остаются в истории для проектов с закреплёнными редакциями.

Проверка на ГОСТ Р 52290-2024 (локально, PDF в репозиторий не входит): страницы 25–67, 368 изображений, 395 кодов с 27 вариантами `_ж`; все номера найдены, набор совпадает с кодами прежнего архива, кроме рисуемых программой 3.24/8.1.1 и варианта 6.14.1_v2. Разбор PDF занимает несколько секунд. Если PDF отсканирован или устроен иначе, используйте загрузку из ZIP.

## Загрузка из ZIP (прежний способ)

Пользовательский ZIP содержит две папки: `PNG с номером` и `PNG без номера`. Для каждого кода знак должен присутствовать в обеих папках. Приложение читает архив с компьютера составителя, проверяет имена, пары и PNG, затем хранит изображения в `private-data/registry.sqlite`. Набор изображений не включается в GitHub и не подпадает под лицензию кода проекта.

В предоставленном архиве 420 кодов и 840 PNG. Коды совпадают с 420 обозначениями знаков автономного прототипа, однако совпадение имени не подтверждает точность изображения или применимость конкретного знака.

В «Реестры» → «Импорт Excel и знаков» выберите ZIP, введите документ и редакцию ГОСТ и, при желании, приложите PDF. В этом способе PDF используется только для локального SHA-256. Просмотр покажет число новых, изменённых, неизменных и исключаемых кодов. Подтверждение создаёт резервную копию SQLite, затем заменяет активный набор; удалённые из новой версии коды больше не выдаются API. Старые PNG и происхождение редакций остаются в базе. Повторный импорт той же редакции и тех же PNG не создаёт новую редакцию.

Команда `npm run import:signs -- путь/к/архиву.zip` по-прежнему позволяет просматривать и импортировать ZIP из CLI; `--apply` создаёт резервную копию. CLI без указанного источника помечает редакцию как неизвестную, поэтому для печати чернового листа с этим каталогом потребуется повторный импорт из интерфейса с указанием редакции.

Ранее автоматически трассированные SVG удаляются из существующей базы при первом запуске новой версии. В каталоге остаются оба исходных PNG. Для печатного применения изображений требуется сверка их происхождения и качества с ответственным специалистом.

Локальный API выдаёт метаданные `/api/signs` с номером редакции каждого активного кода, источник `/api/signs/catalog` и изображения `/api/signs/{код}/image` (без номера) или `?numbered=1` (с номером), всегда в формате PNG. Закреплённый исторический PNG доступен с `?rev=N` (при необходимости вместе с `numbered=1`); он выдаётся с `Cache-Control: private, max-age=31536000, immutable`. Новые и изменённые стойки принимают только коды активного локального набора; старые JSON могут содержать отсутствующие коды, которые показаны предупреждением. На черновом листе печать блокируется, если нужного PNG нет или источник не имеет указанной редакции. Знаки машины и переносного комплекса также берутся из локального каталога (PDF или ZIP); их условные корпуса и фигура регулировщика отрисованы интерфейсом и требуют предметной сверки с источниками.

На этапе «Знаки и объекты» после применения правок нажмите «Закрепить редакции PNG» и сохраните проект. Файл v5 запишет редакции всех использованных кодов, включая знаки машины прикрытия и переносного комплекса, и источник каталога. При изменении набора использованных кодов закрепление автоматически очищается; закрепите редакции заново. Лист и рабочая область такого проекта продолжают брать исторические PNG после обновления или исключения кода из активного каталога. Файлы, созданные до этого действия, используют текущие изображения. История изображений должна оставаться в локальной SQLite: для переноса на другой компьютер нужны файл проекта и разрешённая резервная копия соответствующего каталога. Изображения ГОСТ и ПУ-66 не публикуйте в PR. Наличие PNG не подтверждает применимость знака к конкретной схеме.

При повторном импорте того же PNG с новой меткой редакции создаётся запись каталога, но байты и номер редакции изображения не дублируются. Новая графика или возвращение исключённого кода создаёт редакцию PNG.

## Новая редакция стандарта знаков

1. В «Реестры» → «Нормативные документы» добавьте PDF новой редакции ГОСТ Р 52290 с датой введения. До этой даты действующей остаётся прежняя редакция.
2. Когда новая редакция вступила в силу, раздел документов, импорт знаков и лист предупреждают, что каталог загружен по прежней редакции.
3. В «Импорт Excel и знаков» выберите новую редакцию в блоке «Знаки из PDF стандарта» и нажмите «Извлечь знаки из PDF» (для отсканированного PDF — ZIP в блоке «Загрузка знаков из ZIP»). Просмотр покажет новые и исключаемые коды, знаки только со сменой источника и изменённые изображения рядом с текущими.
4. После подтверждения каталог переходит на новую редакцию; прежние PNG остаются в истории. Проекты с закреплёнными редакциями продолжают показывать прежние изображения и предупреждают, что закреплена устаревшая редакция: после проверки закрепите знаки заново на этапе «Знаки и объекты».

Документ, с которым сверен импорт каталога, нельзя удалить из библиотеки: он нужен для истории.
