# Локальный каталог дорожных знаков

Пользовательский ZIP содержит две папки: `PNG с номером` и `PNG без номера`. Для каждого кода знак должен присутствовать в обеих папках. Приложение читает архив с компьютера составителя, проверяет имена, пары и PNG, затем хранит изображения в `private-data/registry.sqlite`. Набор изображений и его производные не включаются в GitHub и не подпадают под лицензию кода проекта.

В предоставленном архиве 420 кодов и 840 PNG. Коды совпадают с 420 обозначениями знаков автономного прототипа, однако совпадение имени не подтверждает точность изображения или применимость конкретного знака.

Команда `npm run import:signs -- путь/к/архиву.zip` показывает число новых и изменённых знаков без записи. `--apply` сохраняет их после резервного копирования SQLite. С `--vector` дополнительно трассируется PNG без номера: в базе сохраняется настоящий SVG с путями и цветными областями. Исходный PNG не удаляется. Импорт повторяем: одинаковые изображения не создают новую редакцию, а замена PNG без повторной трассировки удаляет устаревшую SVG-производную.

Трассировка автоматически приближает контуры пиксельного изображения. Она может изменить тонкие линии, цифры, антиалиасинг и геометрию. Наличие SVG не означает, что он идентичен нормативному оригиналу. Для точного вывода до предметной проверки используйте исходный PNG; проверку SVG проводите визуально на нужном масштабе. Исходных векторных файлов в предоставленном ZIP нет. Если позднее появятся разрешённые исходные SVG, их можно будет добавить отдельным импортом с проверкой происхождения и безопасности содержимого.

Локальный API выдаёт метаданные `/api/signs` и изображения `/api/signs/{код}/image?format=png` (без номера), `?format=png&numbered=1` или `?format=svg`. Каталог в интерфейсе позволяет искать коды и сравнивать PNG с производным SVG. Знаки из открытого JSON-проекта сверяются с наличием в каталоге; размещение на листе ещё не перенесено.
