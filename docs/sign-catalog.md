# Локальный каталог дорожных знаков

Пользовательский ZIP содержит две папки: `PNG с номером` и `PNG без номера`. Для каждого кода знак должен присутствовать в обеих папках. Приложение читает архив с компьютера составителя, проверяет имена, пары и PNG, затем хранит изображения в `private-data/registry.sqlite`. Набор изображений не включается в GitHub и не подпадает под лицензию кода проекта.

В предоставленном архиве 420 кодов и 840 PNG. Коды совпадают с 420 обозначениями знаков автономного прототипа, однако совпадение имени не подтверждает точность изображения или применимость конкретного знака.

В «Реестры» → «Импорт Excel и знаков» выберите ZIP, введите документ и редакцию ГОСТ и, при желании, приложите PDF. PDF используется только для локального SHA-256, **извлечения и проверки изображений по PDF нет**. Просмотр покажет число новых, изменённых, неизменных и исключаемых кодов. Подтверждение создаёт резервную копию SQLite, затем заменяет активный набор; удалённые из новой версии коды больше не выдаются API. Старые PNG и происхождение редакций остаются в базе. Повторный импорт той же редакции и тех же PNG не создаёт новую редакцию.

Команда `npm run import:signs -- путь/к/архиву.zip` по-прежнему позволяет просматривать и импортировать ZIP из CLI; `--apply` создаёт резервную копию. CLI без указанного источника помечает редакцию как неизвестную, поэтому для печати чернового листа с этим каталогом потребуется повторный импорт из интерфейса с указанием редакции.

Ранее автоматически трассированные SVG удаляются из существующей базы при первом запуске новой версии. В каталоге остаются оба исходных PNG. Для печатного применения изображений требуется сверка их происхождения и качества с ответственным специалистом.

Локальный API выдаёт метаданные `/api/signs` с номером редакции каждого активного кода, источник `/api/signs/catalog` и изображения `/api/signs/{код}/image` (без номера) или `?numbered=1` (с номером), всегда в формате PNG. Закреплённый исторический PNG доступен с `?rev=N` (при необходимости вместе с `numbered=1`); он выдаётся с `Cache-Control: private, max-age=31536000, immutable`. Новые и изменённые стойки принимают только коды активного локального набора; старые JSON могут содержать отсутствующие коды, которые показаны предупреждением. На черновом листе печать блокируется, если нужного PNG нет или источник не имеет указанной редакции. Знаки машины и переносного комплекса также берутся из архива; их условные корпуса и фигура регулировщика отрисованы интерфейсом и требуют предметной сверки с источниками.

На этапе «Знаки и объекты» после применения правок нажмите «Закрепить редакции PNG» и сохраните проект. Файл v5 запишет редакции всех использованных кодов, включая знаки машины прикрытия и переносного комплекса, и источник каталога. При изменении набора использованных кодов закрепление автоматически очищается; закрепите редакции заново. Лист и рабочая область такого проекта продолжают брать исторические PNG после обновления или исключения кода из активного каталога. Файлы, созданные до этого действия, используют текущие изображения. История изображений должна оставаться в локальной SQLite: для переноса на другой компьютер нужны файл проекта и разрешённая резервная копия соответствующего каталога. Изображения ГОСТ и ПУ-66 не публикуйте в PR. Наличие PNG не подтверждает применимость знака к конкретной схеме.

При повторном импорте того же PNG с новой меткой редакции создаётся запись каталога, но байты и номер редакции изображения не дублируются. Новая графика или возвращение исключённого кода создаёт редакцию PNG.
