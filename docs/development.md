# Разработка, запуск и сборка

[Каталог документации](README.md) · [Правила изменений](../CONTRIBUTING.md)

## Среда

Нужны Git, npm и Node.js 24 от 24.12.0 либо Node.js 26 от 26.7.0, в пределах соответствующей основной версии. Точные ограничения заданы в `package.json`, обычная версия — в `.nvmrc`. Используйте `npm ci` и существующий lockfile. API запускается напрямую из TypeScript средствами Node.js.

```bash
npm ci
npm run dev
```

Интерфейс: `http://127.0.0.1:5173/`, API: `http://127.0.0.1:4100/`. Оба слушают `127.0.0.1`. Не открывайте `index.html` двойным щелчком. Docker и внешняя база не нужны. Для собранной версии выполните `npm run build`, затем `npm run local` и откройте порт 4100.

## Локальные данные и переменные окружения

| Настройка                           | Область действия                                                                                                  |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `TOD_DATABASE_PATH`                 | Явный путь к базе для API, desktop и CLI; используйте отдельную временную базу для экспериментов                  |
| `TOD_PORT`                          | Начальный порт desktop/exe; при занятом порте подбирается следующий. Не меняет порт Vite-прокси или `npm run dev` |
| `TOD_NO_BROWSER` или `--no-browser` | Desktop/exe без автоматического открытия браузера                                                                 |
| `TOD_E2E_EXE`                       | Проверка готового exe в Playwright вместо dev-сервера                                                             |

У `npm run dev` и `npm run local` база по умолчанию — `private-data/registry.sqlite` репозитория. У desktop без `TOD_DATABASE_PATH` папка данных выбирается относительно исполняемого Node.js или SEA-файла с переходом в профиль пользователя при отсутствии права записи. Для проверки `npm run desktop` удобно явно задать отдельный путь к базе.

`local-input/`, `private-data/`, `dist/` и `release/` не включаются в Git. Рабочие данные не используются в публичных тестах. Выбор изображения закреплённой редакции проходит через обязательную сверку ETag; fingerprint базы в `/api/status` не содержит путь.

## CLI импорта и резервных копий

Остановите приложение перед большим импортом через CLI. Команда без `--apply` только показывает план, с `--apply` записывает пакет после резервного копирования.

```bash
npm run import:pu66 -- "local-input/card-1.xlsx"
npm run import:pu66 -- --apply "local-input/card-1.xlsx"
npm run import:signs -- "local-input/signs.zip"
npm run import:signs -- --apply "local-input/signs.zip"
```

CLI знаков работает с ZIP и не подтверждает редакцию по PDF. Для выпуска укажите и проверьте источник каталога в интерфейсе; ограничения описаны в [каталоге знаков](sign-catalog.md).

Перед изменением схемы базы программа сама сохраняет прежний файл как `backups/registry-before-update-v<версия>-<время>.sqlite`; без этой копии обновление не выполняется. Копии автоматически не удаляются. `npm run backups:prune` показывает план очистки: последние 20 копий, возраст 90 дней, минимум одна сохраняется. Пороги можно изменить: `npm run backups:prune -- --keep 30 --max-age-days 180`. Удаление выполняется только с `--apply`, после проверки списка и требований организации. Другие имена файлов, включая копии перед обновлением, не затрагиваются.

## Windows-сборка и CI

`npm run build:exe` упаковывает интерфейс и Node.js-сервер в `release/editor-of-tod.exe` и сохраняет рядом лицензии. Сборка разрешена на Windows и Linux. Процесс GitHub Actions «Windows exe» запускается вручную; автоматического выпуска нет. Проверки SEA на текущей системе и Windows описаны в TESTING.MD. В CI браузерный сценарий, упавший из-за сбоя агента, повторяется до двух раз и помечается в отчёте как «flaky»; локально повторов нет. Изменения старых данных проверяются до выпуска новой сборки.

Обычный CI выполняет `npm run check` на Linux/Node 24 и Windows/Node 26.7.0 и отдельные браузерные сценарии на Linux. Проверка лицензий остаётся обязательной: новые зависимости программы разрешены только по списку в `scripts/third-party-licenses.ts`.
