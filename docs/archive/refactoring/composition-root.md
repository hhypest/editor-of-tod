`server/composition-root.ts` собирает конкретные SQLite-адаптеры в `createServerServices(path, now)`. ServerRuntime связывает сервисы с HTTP/CLI-портами; совместимый фасад удалён после перевода вызывающих. Репозитории и прикладные сценарии не импортируют composition root или фасад.

## Инициализация и владение

Порядок сохранён: открыть одно соединение с прежними настройками → migration runner/backup → источники, проекты/recovery/legacy → ПУ-66 → знаки/документы/текст/подтверждения/удаление → наполнить пустой нормативный реестр. Каждый адаптер и TransactionRunner получает то же соединение. Общие ProjectSourceStore и Pu66KeyResolver создаются один раз, запросы lifecycle и исторических ссылок знаков связаны напрямую с соответствующим владельцем.

При ошибке миграции, сборки или seed выполняются прежний best-effort ROLLBACK и close, затем пробрасывается исходная ошибка. После успешного возврата соединением владеет вызывающий; runtime сохраняет close, schemaVersion, ручной backup и migration metadata. Root не создаёт вторую базу и не меняет границы транзакций. Seed по-прежнему вызывает отдельное сохранение для каждой записи: отказ второй записи не отменяет первую уже зафиксированную. Непустой реестр автоматически не дополняется.

Часы передаются через callback без собственного receiver. Если callback требует receiver, вызывающий привязывает его явно через bind; тесты проверяют сохранение этого контекста. Количество/порядок вызовов в миграциях, seed и предметных операциях сохранены. Начальное наполнение использует напрямую LegacyRegistryRepository.

Возвращаемый ServerServices предназначен для сборки приложения. Это не публичный service locator для маршрутов: HTTP-группы получают только нужные им операции. Объект соединения не передаётся в маршруты. [ServerRuntime](server-runtime-bootstrap.md) теперь связывает сервисы напрямую с HTTP-группами и CLI-командами, владеет metadata/backup/close. Рабочие API/CLI/desktop не создают совместимый фасад; проверка уже работающего desktop по-прежнему происходит до открытия базы. [Фасад и совместимый тестовый адаптер удалены](facade-removal.md). Тесты используют владельцев и composeServerRuntime на том же соединении, без копии domain forwarding methods.

## Проверки

Два новых [контракта инициализации фасада](../../../server/__tests__/database-contracts.test.ts) прошли до переноса: закрытие после отказа миграции с успешным повтором после ремонта вымышленной схемы и закрытие после второго seed с сохранением первой записи/истории/исходной ошибки. Существующие контракты сохраняют future schema без изменения байтов, миграционные/ручные backup и receiver часов.

Три [интеграционные проверки root без RegistryStore](../../../server/__tests__/composition-root.test.ts) фиксируют общие источники проекта/recovery, связь import/lifecycle/verification ПУ-66, исторические ссылки знаков в guards документов и общую атомарную команду удаления. Все SQLite/PDF/изображения/карточки создаются из вымышленных данных. Полный check, frozen-format/миграционные/API/конкурентные проверки и E2E остаются обязательными.

JSON v10/SQLite v13, HTTP-контракты, нормативные алгоритмы и лист сохраняются. Новых зависимостей нет. А4 открыт; HTTP-примитивы, группы маршрутов и рабочий bootstrap/runtime выделены. Фасад удалён; далее включение завершающего шага и фиксация итоговых проверок main/Windows exe. Pinia #191 первой после А4; новые функции после всей технической очереди.
