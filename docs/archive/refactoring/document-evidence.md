## Текст страниц

Чтение сортируется по page; отсутствие строк возвращает null. Пустой результат извлечения сохраняется одной пустой страницей, поэтому скан без текста не разбирается повторно. Строки, включая Unicode, переводы строк, пустые страницы и пробелы, записываются без нормализации.

Замена сохраняет прежние BEGIN IMMEDIATE → DELETE → вставки страниц с номерами от 1 → COMMIT. Ошибка любой вставки откатывает удаление старых страниц и все новые строки. BEGIN остаётся перед try: отказ вложенного запуска не откатывает внешнюю транзакцию. Другой connection до commit читает старые страницы и не может писать во время замены.

Repository не извлекает PDF, не вызывает часы, не открывает/закрывает SQLite и не мигрирует. Извлечение остаётся в существующем documentText: сначала cache, затем getPdf/extract/save; отсутствие PDF и ошибка чтения сохраняют прежние reason/field/status.

## Подтверждения параметров

Add сохраняет прежний INSERT RETURNING id: входные поля и JSON.stringify(value), отдельный recorded_at по часам, ответ как исходный input с новым id. Число, таблица, nullable documentId/page, цитата, фрагмент, автор, дата и примечание не меняются. Повторное подтверждение добавляет новую строку. Возвращённый value, как прежде, принадлежит входному объекту; последующее чтение восстанавливает его из JSON.

List сохраняет ORDER BY parameter_id, id и прежний row mapper/property order. Технический recorded_at не входит в API-проекцию. Последнее подтверждение выбирается существующим алгоритмом по порядку id, не по confirmedAt. Неверный сохранённый JSON вызывает прежний отказ JSON.parse. Новая низкоуровневая валидация не добавлена: проверка запроса и допустимого значения остаётся в прикладном сценарии confirmParameter.

Новой явной транзакции вокруг add нет. Ошибка часов не вставляет запись; отказ SQL/trigger откатывает отдельную вставку и не завершает внешнюю транзакцию вызывающего кода. Repository получает часы через прежнюю обёртку фасада с сохранением receiver.

## Границы и проверки

Существующий normative-parameters.ts получает NormativeParameterStorage из семи нужных операций вместо RegistryStore; documentText получает только cache/PDF/save. Тела функций, включая поиск цитат/изменений, fingerprints, проверку актуального документа и сообщения отказов, сохранены. Ошибки RevisionConflict используют тот же конструктор через прямой импорт storage-errors. HTTP, формат и вычисления нормативных правил не меняются.

Три [контракта фасада](../../../server/__tests__/document-evidence-contracts.test.ts) предварительно прошли до переноса: cache/rollback/nested BEGIN, история/property order/value/clock receiver и ошибки вставки. Семь [прямых проверок](../../../server/__tests__/document-evidence-repositories.test.ts) без RegistryStore фиксируют отсутствие скрытой инициализации, read-only, порядок страниц, rollback/FK, видимость/блокировку второго соединения, JSON/null/order/ошибки, внешнюю транзакцию, reopen и узкие cache/parameter ports. Существующие проверки параметров, отказов API, frozen JSON/SQLite и полный E2E сохраняются.

Тела всех четырёх перенесённых методов и всех функций/конструкторов normative-parameters.ts совпадают с исходными после переименования методов. JSON v10/SQLite v13, поля #110, нормативные алгоритмы и выпускной лист сохраняются. Тестовые PDF/текст/подтверждения вымышлены, новых зависимостей нет.
