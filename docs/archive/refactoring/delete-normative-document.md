`server/documents/delete-normative-document.ts` координирует удаление через узкие операции документов, текста, подтверждений и исторических партий знаков. RegistryStore делегирует deleteDocument одной команде execute. Это структурный перенос после отдельного [исправления атомарности #215/#216](document-deletion-atomicity.md), без нового изменения поведения.

## Сценарий и владельцы

DeleteNormativeDocument получает Pick-контракты repository и синхронный TransactionRunner. Внутри одной прежней BEGIN IMMEDIATE порядок сохраняется: существование → ссылки любых партий знаков → прикреплённые изменения → подтверждения → удаление страниц → удаление PDF/метаданных. Неизвестный id возвращает false под блокировкой; DocumentInUse и их порядок не меняются. Отказ чтения/удаления откатывает команду; отказ вложенного BEGIN не откатывает транзакцию вызывающего.

- NormativeDocumentRepository владеет прежним DELETE normative_documents; проверки и общий commit принадлежат команде.
- DocumentTextRepository владеет прежним DELETE document_pages без собственной транзакции: он участвует в общей транзакции удаления. Прежняя самостоятельная save текста не переписана.
- ParameterConfirmationRepository получает countForDocument по всем историческим подтверждениям; SQL не выбирает только последнее значение параметра.
- SignCatalogDocumentReferences владеет прежним COUNT по всем sign_catalog_batches. Это узкое чтение модуля знаков, не перенос всего каталога. Тот же владелец обслуживает запрет смены kind документа в NormativeDocumentService, устраняя дублирование SQL в фасаде.

Владельцы используют одно существующее соединение, не открывают/закрывают его, не мигрируют и не создают backup. Команда не импортирует RegistryStore, DatabaseSync или HTTP. Временная сборка зависимостей остаётся в фасаде до общего composition root по [серверному плану](server-god-object-plan.md).

## Сохранность и проверки

Полное тело callback исходной транзакции совпадает после замены операций на порты; семь SQL/error-литералов перенесены точно. Сохраняются проверки до записей, видимость прежнего PDF/текста до commit, блокировка новой ссылки из второго соединения, полный rollback и повтор после отказа. Другие документы, PDF, тексты, подтверждения и партии не удаляются. Форматы JSON v10/SQLite v13, HTTP 403/500/409/200/404, нормативные алгоритмы, поля #110 и лист не меняются.

Семь [регрессионных проверок фасада](../../../server/__tests__/document-deletion.test.ts) повторно прошли до переноса. Проверка первой блокировки теперь наблюдает фактический NormativeDocumentRepository.get вместо forwarding method фасада; ожидания блокировки/сохранности не ослаблены, она проходит и до, и после переноса. Остальные regressions #215, включая ошибки DELETE и HTTP, сохранены.

Семь [прямых проверок команды](../../../server/__tests__/delete-normative-document.test.ts) без RegistryStore покрывают historical/read-only references/no init, точный порядок проверок под транзакцией, оба отказа DELETE, блокировку новой ссылки до первого чтения и между DELETE, rollback чтения/nested BEGIN и read-only reopen с посторонней историей/PDF. Сохраняются полный check, старые API/frozen JSON/SQLite и E2E. Тестовые PDF/сведения вымышлены, новых зависимостей нет.

[Каталог знаков](sign-catalog.md) также выделен: batch/active/history/PNG/relabel/retire с прежними транзакциями. Далее composition root и маршруты. #135/А4 пока открыты, Pinia первой после А4; новые функции после всего технического этапа.
