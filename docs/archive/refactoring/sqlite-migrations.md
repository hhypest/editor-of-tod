## Владельцы ответственности

- `server/database/connection.ts` открывает и настраивает соединение с прежними правами и ограничениями.
- `server/database/schema-version.ts` владеет текущей версией и чтением `PRAGMA user_version`. Экспорт `SCHEMA_VERSION` из `server/store.ts` сохранён для прежних вызывающих.
- `server/database/migration-runner.ts` проверяет исходную версию, создаёт обязательную копию через существующий backup-модуль и выполняет явные переходы. После каждого шага проверяется фактически установленная версия.
- `server/database/migrations/` содержит отдельный модуль каждого перехода. Общей транзакции вокруг всех шагов нет: прежние SQL и границы транзакций сохранены.
- `RegistryStore` сохраняет публичный фасад и владельца соединения. Он получает metadata обновления, затем отдельно заполняет начальный нормативный реестр, если тот пуст; при ошибке закрывает соединение. Миграции не знают предметных репозиториев и не наполняют реестры нормативными записями.

Новая база идёт `0 → 1 → 3 → … → 13`. Версия 2 — самостоятельная историческая ветка; при создании новой базы она не появляется. Эти переходы воспроизводят прежние условия конструктора, а не вводят новую схему хранения.

## Копия, ошибка и повтор

Неизвестная будущая версия отклоняется до резервной копии и изменений. Для поддерживаемой старой файловой базы создаётся одна копия перед первым шагом. При отказе копирования миграции не начинаются. Текущая v13 не создаёт копию и не выполняет DDL. Для базы в памяти копии нет.

**Особый v2:** прежние векторные данные удаляются с `secure_delete` и фиксацией транзакции. Затем `VACUUM` выполняется вне транзакции, и только после успеха версия становится 3. Копия v2 не создаётся, чтобы не сохранять удаляемые SVG. Если `VACUUM` не прошёл, версия остаётся 2; повтор допускает уже отсутствующую колонку и снова очищает файл.

Ошибка шага откатывает незавершённую транзакцию, сохраняя исходную ошибку и уже созданную копию. Ранее завершённые шаги остаются завершёнными, как в прежнем конструкторе; обновление не объявляется одной общей атомарной транзакцией. Вызов внутри чужой открытой транзакции отклоняется без её отката. Прямой вызывающий `migrateDatabase` владеет соединением и может повторить операцию либо закрыть его; production-фасад закрывает соединение при отказе.

Переход станционных ключей содержит локальное описание исторического `cardNumber` и прежний селектор ключей. Он сохраняет SQL, порядок переноса редакций/сверок и значение неоднозначного alias; последующее развитие текущей модели карточки не должно менять старую миграцию.

## Свидетельства совместимости

- Существующие [frozen-formats](../../../server/__tests__/frozen-formats.test.ts) проверяют SQL-фикстуры v3–v13, снимки и повторное открытие.
- [imports](../../../server/__tests__/imports.test.ts) проверяет синтетические v1/v2, удаление SVG без потери PNG и станционные aliases/сверки.
- [store](../../../server/__tests__/store.test.ts) сохраняет проверки отказа backup, rollback, metadata и отсутствия повторной копии.
- [database-contracts](../../../server/__tests__/database-contracts.test.ts) проверяет неизменность будущей версии и контекст переданного источника времени.
- [migration-runner](../../../server/__tests__/migration-runner.test.ts) проверяет новую границу независимо от RegistryStore: ветки 0/1/2/12/13, временную базу, будущую версию, отказ backup, прерванный шаг с повтором, отсутствие ложного успеха и повтор v2 после неудачного VACUUM.

При переносе отдельно сопоставлены все 36 строковых литералов прежних миграций с новыми модулями: содержимое и порядок совпадают. Это дополнительная проверка дословного переноса; она не заменяет тесты на SQLite, API и полный E2E.
