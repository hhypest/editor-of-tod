## Парсер и граф

`scripts/check-architecture.ts` читает рабочие TS/TSX/MTS/Vue/MJS-модули src/server, исключая `__tests__` и декларации. Vue разбирается официальным `@vue/compiler-sfc.parse`, отдельно для script и script setup. Регулярного выражения для извлечения script нет. HTML-комментарии не превращаются в код, атрибут с `>` не обрывает блок. Ошибки структуры SFC сообщаются с путём и доступной позицией; неизвестный script lang отклоняется. JS/JSX/TS/TSX поддерживаются. `script src` создаёт отдельное ребро зависимости.

TypeScript AST по-прежнему извлекает import, type import, re-export, import type expressions и literal `import()`. Относительные пути и `@/` нормализуются, query/hash suffix снимаются перед поиском точного модуля, расширения или index. Raw-импорт кода остаётся ребром; raw-текстовые активы вроде LICENSE не входят в граф. Неизвестный локальный модуль — ошибка. Циклы, включая type-only и динамические статические рёбра, запрещены.

`import('path')` и шаблонная строка без подстановок разрешаются статически. `import(variable)`, конкатенация и шаблон с подстановкой дают явное `non-static dynamic import cannot be checked`. Вычисление переменных и allowlist для обхода этой ошибки не вводятся.

## Декларативная матрица

`scripts/architecture-policy.ts` содержит именованные пересекающиеся селекторы путей и список запрещённых направлений. Код обхода AST/разрешения пути не содержит отдельных условий для каждого слоя.

| Откуда                                  | Куда                                                    | Политика                                   |
| --------------------------------------- | ------------------------------------------------------- | ------------------------------------------ |
| src (клиент)                            | server                                                  | Запрещено                                  |
| domain/application                      | components, composables, services, presentation, stores | Запрещено                                  |
| domain                                  | application                                             | Запрещено                                  |
| domain review-модули                    | domain/sheet-drawing.ts                                 | Запрещено                                  |
| domain/application                      | внешний пакет pinia и его подпути                       | Запрещено, включая query suffix            |
| Остальные разрешённые статические рёбра | Локальные модули                                        | Проверяются разрешение и отсутствие циклов |

Прежние сообщения запретов сохранены, все прежние негативные фикстуры остаются без ослабления ожиданий. Сервер может использовать ядро, UI/stores — services и domain. Это фиксация существующих границ, без массового переноса модулей или новых фасадов.

## Ограничения

Проверка не доказывает предметную корректность, транзакционность, качество разделения ответственности или отсутствие ошибок во время исполнения. Это не универсальная реализация TS/Vite resolver: поддерживается фиксированный список расширений, относительные пути и один алиас `@/`. Внешние пакеты, кроме явного запрета Pinia для core, не раскрываются в локальный граф. CJS require, import.meta.glob, code generation и косвенный runtime loading не моделируются; перед их использованием нужно отдельно определить проверяемую границу. Template/style зависимости и семантика Vue macros/generic constraints не анализируются. Ошибки TypeScript и макросов продолжают проверять штатные type-check/build.

ESLint отдельно сохраняет запреты Vue, Node imports и browser globals для core. Архитектурный анализатор дополняет эти правила. Нормативные расчёты, JSON v10/SQLite v13, HTTP/SQLite, поля #110 и лист/PNG не меняются.

## Зависимость и проверка

`@vue/compiler-sfc` 3.5.44 закреплён как прямая devDependency: эта же версия уже была транзитивной в lockfile. MIT проверена по package metadata и файлу LICENSE установленного пакета. Integrity/версии дерева зависимостей не обновляются; добавлена только прямая запись владельца инструмента. В программу новый runtime-компонент не добавляется, сборка лицензий остаётся включённой.

Локально прошли 36 сценариев самого анализатора, type-check, ESLint затронутого кода и `check:architecture` на 221 рабочем модуле. Покрыты оба SFC script-блока, ложные script в комментариях, повреждённый SFC, script src/lang, aliases/index/query, type/re-export/literal dynamic imports, нестатические imports, raw assets/modules, Pinia и циклы. Эти проверки проверяют новый механизм контроля; итоговый check/E2E, тестирование состояния и Windows exe остаются после полного погашения технического долга. Результаты автоматического CI фиксируются в PR для его head/tree.
