Из `server/index.ts` выделены три группы: `http/routes/signs.ts`, `documents.ts` и `normative-parameters.ts`. Они содержат 13 прежних внешних ветвей, включая ветвь адреса документа с семью внутренними обработчиками. Группы не импортируют RegistryStore/DatabaseSync и не содержат SQL. Прикладные ZIP/PDF/нормативные сценарии и владельцы транзакций сохраняются.

## Зависимости

| Группа                | Получаемые операции                                                                                 |
| --------------------- | --------------------------------------------------------------------------------------------------- |
| Знаки                 | catalog list/latest/getMetadata/getPng; существующие команды ZIP plan/import/document/backup        |
| Документы             | library list/getPdf/update/delete; существующие DocumentImportCommands и SignImportCommands для PDF |
| Нормативные параметры | существующий NormativeParameterStorage: документы, cache текста и история подтверждений             |

`createRegistryServer` сохраняет сигнатуру, собирает callback к прежним методам фасада на прежнем receiver и передаёт их в группы. Прямые тесты связывают группы с `createServerServices`, repositories/services и отдельным backup callback, без RegistryStore.

Контекст `ParameterRouteContext` создаётся на каждый запрос. Он получает ID только после совпадения POST confirm и до чтения JSON. Общий catch по-прежнему строит `ParameterRejection` из ошибки и этого ID; finish-диагностика сохраняет allowlist причин и не получает body/свободный текст. Контекст не хранится в замыкании общей группы.

## Сохранённые контракты

- Host/Origin проверяются до групп; непересекающиеся адреса знаков, параметров и документов разрешаются теми же условиями. Несовпадение возвращает false, не читая тело и не отправляя ответ. Status/diagnostics/legacy/backup затем выделены в [отдельные группы](system-legacy-routes.md); static/fallback остаётся в index.
- Поиск знаков: 80 символов, limit 2000; однократное декодирование кода. `metadata` требует положительный safe-integer rev; `image` допускает текущую версию и сохраняет format/numbered/rev. Исторические размеры/байты, PNG/security/cache headers, ETag/304 не подменяются действующим каталогом.
- Числовой document path сохраняет ведущие нули, safe integer, прежние 404/405 и порядок проверок. PDF/имя файла/заголовки, update schema и атомарный delete передаются прежним владельцам.
- ZIP принимает прежний транспортный лимит 60 МиБ; PDF identify/preview/apply — 56 МиБ; остальные JSON — 64 КиБ. Внутренние лимиты файлов/base64 не меняются.
- Preview без записи, fingerprint, backup, post-backup recheck, no-op знаков без backup и явное разрешение изображений PDF остаются в прежних сценариях. Граница fingerprint не переносится внутрь транзакции этим структурным изменением.
- Подтверждения сохраняют документ/цитату/страницу/историю, 400/404/409 и reason/field. Алгоритмы, нормативные числа, JSON v10/SQLite v13, SVG/печать/экспорт не меняются.

## Проверки и остаток

Три [предварительных контракта](../../../server/__tests__/catalog-document-api-contracts.test.ts) прошли на исходном index: поиск/декодирование/версии PNG; числовые пути/методы/лимиты документов; детали ошибок подтверждений и finish-диагностика.

Девять [прямых HTTP-проверок](../../../server/__tests__/catalog-document-routes.test.ts) без фасада охватывают:

- исторические PNG/metadata после исключения из каталога, numbered и ETag/304;
- ZIP preview больше 64 КиБ, stale plan, apply/no-op и смену документа во время backup;
- PDF identify/preview/apply/duplicate, точные байты, реквизиты и удаление текста;
- изменение плана импорта документа во время backup;
- PDF signs preview/явное исключение/PNG yellow/apply/no-op, запрет удаления и смены kind при ссылке партии;
- rollback удаления PDF/текста и запрет удаления при amendment;
- решения и подтверждения по документу, конфликт источника, историю, параллельные отказы с отдельным контекстом;
- untouched fallback всех трёх групп без вызова зависимостей.

AST-сверка с исходным index подтверждает условия и тела всех 13 перенесённых внешних ветвей (включая внутренние обработчики документа) после замены зависимостей, request-контекста и повторного разбора URL на переданный URL. Остальные 10 ветвей и fallback совпадают.

Полный `npm run check`, E2E и прежние frozen-format/SQLite/API/конкурентные проверки обязательны. Проверка Windows Node в CI не считается проверкой exe или целевого ПК. Отдельная сборка exe этим шагом не запускается.

[System/diagnostics/legacy](system-legacy-routes.md) затем выделены. Далее bootstrap/shutdown и удаление forwarding methods после перевода всех вызывающих. #135/А4 открыты; Pinia остаётся первой после А4.
