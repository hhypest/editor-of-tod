## Как поддерживать документы

[Предметная сверка для 0.3.0](subject-review-0.3.0.md) выделяет незакрытые решения перед зависимыми изменениями, приёмку внутри версии и принятое распределение ответственности за пользовательскую графику.

README остаётся короткой точкой входа. Пользовательские инструкции обновляются в руководстве и встроенной справке; команды и устройство — в профильных документах. Новое поведение фиксируется в CHANGELOG, выполнение задач — в ROADMAP, причины архитектурного выбора — в ADR. Возможности прототипа и предложения не отмечаются как реализованные функции.

[Переработка интерфейса вокруг рабочих задач](interface-workflows.md): история замечаний и успешной повторной приёмки И3, новый сценарий настройки и отложенная очередь изменений.

- [Технический долг #137](refactoring/debt-rules-formats-diagnostics.md) — общие пороги регулирования, независимые старые читатели и список диагностики при сборке.

- [Достаточность проверок #138](refactoring/test-coverage-browsers.md) — настоящие SFC, честное измерение V8 coverage в CI, Chromium/Firefox и диагностика отказов.
