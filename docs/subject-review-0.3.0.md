## Отдельное организационное условие

[#111 — права на графику знаков](https://github.com/hhypest/editor-of-tod/issues/111) остаётся открытым вопросом допустимости использования изображений в выпускаемых документах. Решение должно быть зафиксировано в `docs/licensing.md` до выпуска с соответствующей графикой; если выбран другой способ изображения, его реализацию и проверку оформляют отдельно. Этот документ не делает юридического вывода о наличии прав.

## Что не относится к этой предметной сверке

- #136 — структурное разделение сессии и #134 — сохранность восстановления: технические проверки, а для сна дополнительно проверка рабочего места. Изменение нормативных правил в эти PR не входит.
- #129 — общий путь нового составителя, #130 — рабочие места/браузеры, #139 — независимая сборка и восстановление: эксплуатационная и пользовательская приёмка последующих этапов.
- #131 — версии шаблонов и #137 — унификация правил/читателей остаются отдельными задачами. Структурный перенос сохраняет результаты; любое изменение числа, применимости или основания правила требует собственной предметной сверки перед слиянием.
- #132 — политика хранения относится к организационным решениям, #135/#138/#184 — к техническому долгу. Они не подменяют #103 и #107–#111.

## Как подготовить результаты

1. Для ближайшего зависимого блока выбрать соответствующую строку таблицы и записать конкретные нерешённые вопросы.
2. Подготовить обезличенные примеры для публичных тестов. Рабочие ПУ-66, SQLite, JSON с реальными сведениями, нормативные PDF и рабочие PNG остаются локально.
3. Согласовать исходные решения #103/#110/#107 до изменения зависящего поведения; затем реализовать и проверить техническую часть отдельным PR.
4. Записать предметную приёмку точной сборки. В GitHub публиковать только обезличенный итог, ссылки на задачу и нормативное основание, без исходных файлов.
