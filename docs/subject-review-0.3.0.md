## Принятое решение #110 — 25.10.2026

Состав данных утверждён: ширина проезжей части, все значения видимости карточки с различением направлений и объектов, наименование автодороги, км/пк/станция или перегон; интенсивность авт/ч — по нормативным параметрам технического специалиста. Используются карточки, импортированные специалистом. Ежегодное переутверждение — вне ответственности репозитория/разработчика и не условие выпуска ПО. [Полный контракт и остаток реализации](pu66-data.md). Решение больше не ожидается; API/снимок/лист проверяются после технического долга.

## Закрытое решение об ответственности за графику

[#111 — права на графику знаков](https://github.com/hhypest/editor-of-tod/issues/111) закрыта по решению владельца проекта 25.10.2026. Обеспечение прав на пользовательскую графику относится к ответственности организации, использующей ПО, и технического специалиста; проверка и обеспечение этих прав находятся вне ответственности репозитория и разработчика. Вопрос исключён из открытых задач и условий выпуска 0.3.0 со стороны проекта. Решение закреплено в [лицензировании](licensing.md#ответственность-за-графику-знаков).

## Что не относится к этой предметной сверке

- #136 — завершённое структурное разделение сессии; #134 — принятое восстановление, включая настоящий сон Windows; затем #135/А4 и #191 — серверные границы и общий UI-state. Это технические задачи по сохранённым контрактам, изменения нормативных правил в них не входят.
- #129 — общий путь нового составителя, #130 — рабочие места/браузеры, #139 — независимая сборка и восстановление: эксплуатационная и пользовательская приёмка последующих этапов.
- #131 — версии шаблонов и #137 — унификация правил/читателей остаются отдельными задачами. Структурный перенос сохраняет результаты; любое изменение числа, применимости или основания правила требует собственной предметной сверки перед слиянием.
- #132 — политика хранения относится к организационным решениям, #135/#138/#184 — к техническому долгу. Они не подменяют #103 и #107–#110.

## Как подготовить результаты

1. Для ближайшего зависимого блока выбрать соответствующую строку таблицы и записать конкретные нерешённые вопросы.
2. Подготовить обезличенные примеры для публичных тестов. Рабочие ПУ-66, SQLite, JSON с реальными сведениями, нормативные PDF и рабочие PNG остаются локально.
3. Согласовать исходные решения #103/#110/#107 до изменения зависящего поведения; затем реализовать и проверить техническую часть отдельным PR.
4. Записать предметную приёмку точной сборки. В GitHub публиковать только обезличенный итог, ссылки на задачу и нормативное основание, без исходных файлов.
