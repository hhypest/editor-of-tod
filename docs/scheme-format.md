# Формат проекта версии 4

Текущий экспорт — JSON-объект с `schemaVersion: 4`. Файл можно создать в приложении без старого прототипа или получить импортом v1/v2/v3. JSON обрабатывается в браузере, локальные черновики сохраняются по кнопке в SQLite на этом же компьютере. Формат описывает редактируемый черновик, а не утверждённую схему.

| Поле                               | Содержание                                                                                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `schemaVersion`, `id`, `createdAt` | Версия структуры, UUID и дата создания проекта                                                                                                                                       |
| `crossing`                         | Локальный идентификатор; источник `entered-by-editor`, `legacy-pu66` или `local-pu66`. У первой пары `snapshot: null`, у локальной карточки — ограниченный снимок с номером редакции |
| `template`                         | `b33` или `b34`; ссылка на ОДМ и статус `not-verified`                                                                                                                               |
| `parameters`                       | Участок, направления, расстояния в метрах (неизвестные — `null`), три скорости в км/ч, жёлтый фон и размеры зон работ                                                                |
| `parameters.workZones`             | Для выбранного варианта обязательны положительные размеры отвода, буфера и фронта. Неиспользуемый вариант может иметь значение `null`. Импорт старых проектов сохраняет оба варианта |
| `titleBlock`                       | Редактируемые реквизиты листа; у нового проекта сначала пустые                                                                                                                       |
| `placements`, `nextPlacementId`    | Ручные стойки и элементы, уникальные ID, условные координаты рабочей области; у нового проекта нет автоматических объектов                                                           |
| `source`                           | `{kind: 'created-in-editor'}` для нового проекта либо `{kind: 'legacy-html-v1', importedAt, originalJson}` с точным текстом исходного v1                                             |

## Чтение и сохранение

- Импорт принимает v1 размером до 10 МБ и v2/v3/v4 до 32 МБ. Неизвестная версия и некорректные поля получают явную ошибку. Для v1 сохраняется точный исходный текст, включая ещё не описанные в модели поля. Импорт v2/v3 сохраняет `id`, `createdAt`, параметры, объекты и `source`.
- Старые снимки v2/v3 в SQLite преобразуются в v4 при чтении. Чтение не меняет сохранённые строки. Новая правка или восстановление создаёт редакцию v4; повторное сохранение без изменений не создаёт редакцию.
- В форме создания фронт менее 30 м предварительно выбирает Б.34, от 30 м — Б.33. Ровно 30 м отдельно помечается для проверки. Для созданного в приложении проекта смена длины через эту границу требует создания проекта с новым вариантом; старые данные v1/v2 не меняются. Это правило интерфейса, не проверка применимости схемы. Вводимые скорости и размеры не подставляются из нормативов.
- Редактирование параметров и объектов создаёт новые снимки; отмена и повтор до 30 шагов работают только в текущей вкладке. Изменение расстояний и подписей не перестраивает объекты автоматически. Файл на диске не перезаписывается; сохранённые редакции доступны отдельно.
- Проверка заполнения в интерфейсе вычисляется из открытого применённого снимка v4 и не записывается в JSON или SQLite. Она перечисляет пустые реквизиты, используемые в подписях стоек маркеры `{d300}`, `{d250}`, `{d150}`, `{d50}` без введённого значения и напоминания о ручной сверке. Неприменённый ввод не учитывается; контроль реальных расстояний, правильности знаков и нормативная проверка не выполняются.
- Черновой лист A4 также вычисляется из текущего применённого снимка без изменения JSON. На него попадают только выбранные поля проекта, условные координаты объектов и PNG из локального каталога. Если явно закреплена ПУ-66, из её снимка на лист выводятся только `location`, `axisLabel`, `roadName`, `crossingWidthMetres`; полный `source.originalJson`, остальные данные карточки, номер редакции и время обновления не выводятся. Маркеры расстояний в подписях стоек заменяются введённым числом и `м`, отсутствующее значение остаётся маркером. Лист помечен «Не для согласования» и печатается через диалог браузера; модель печатного листа и нормативная геометрия ещё не утверждены.
- Локальный реестр ПУ-66 не заполняется из проекта, а ручной идентификатор не означает сверки карточки. Составитель может выбрать импортированную карточку, сравнить её поля и явно закрепить локальную редакцию. `crossing.snapshot` тогда содержит только `location`, `axisLabel`, `roadName`, `crossingWidthMetres`, `revision` и `updatedAt`; идентификатор хранится в `crossing.referenceId`. Изменение карточки в реестре не меняет снимок. Файл JSON с этим снимком также конфиденциален. Окончательный состав данных на выпускаемом листе подлежит согласованию.
- Номер знака, геометрия переезда, фактические расстояния и порядок согласования не проверяются. Выбор карточки не подтверждает её актуальность. При передаче схемы передавайте только предусмотренные на ней сведения, без полного реестра ПУ-66 или исходных книг.

Для ручной сверки импорта доступны обезличенные файлы `tests/fixtures/manual-v1.json` (Б.33) и `tests/fixtures/legacy-b34-manual.json` (Б.34). Рабочая область отображает условные координаты; масштаб просмотра не изменяет JSON. Она пока не строит печатный лист.
