# Формат проекта версии 7

Текущий экспорт содержит `schemaVersion: 7` (с 01.10.2026; v6 — с 30.09.2026, до этого — 5). Файлы v1–v6 читаются с преобразованием в памяти; исходные снимки SQLite не переписываются. Новое сохранение создаёт редакцию v7. Прежние версии приложения файлы v7 не откроют. Старые поля из v1 сохраняются точно в `source.originalJson`; файл экспорта остаётся полным и конфиденциальным. В SQLite версии 7 новые редакции хранят SHA-256 ссылку на один локальный исходный текст в `project_sources`. При открытии исходник восстанавливается и проверяется по хешу. Старые редакции продолжают читаться без переписывания; поэтому прежнее повторение в базе не исчезает автоматически.

## Импорт и построение

- Импорт принимает v1 до 10 МБ и v2–v7 до 32 МБ, проверяет известные поля, уникальность ID и числовые значения. Неизвестные поля v1 сохраняются только в исходном JSON; отчёт прямо называет их пути. v2–v6 используют строгие схемы; у файлов v5, сохранённых до появления `signImages`, это поле добавляется с пустым закреплением при чтении.
- v6 → v7: `settlementSpeedKmh` («скорость в населённом пункте») становится `approachSpeedKmh`; при `location: 'out'` прежнее поле не использовалось, поэтому переносится `null`, и отчёт при открытии просит указать скорость. Импорт v1 поступает так же с `params.vIn`. Неприменённый ввод копий восстановления переводится тем же правилом.
- Фронт менее 30 м выбирает Б.34, от 30 м — Б.33 по подтверждённому правилу проекта. Ровно 30 м требует отдельной предметной сверки из-за расхождения подписи и обозначения ОДМ.
- При сборке условного шаблона составитель выбирает местоположение и режим Б.34. Вариант со знаками 2.6/2.7 требует введённой интенсивности ниже порога, достаточной видимости и отгона заданной длины; один регулировщик требует отметки о прямом участке и видимости. Порог (250 авт./ч), отгон (15 м) и шаг ступеней скорости (20 км/ч) — нормативные параметры: до подтверждения действуют значения прототипа, после — подтверждённые по действующей редакции ([docs/standards.md](standards.md)). Проверки основаны на ОДМ 218.6.019, пп. 4.1.8.3, 5.4.4, 12.7.2–12.7.3, рис. Б.33/Б.34 и ГОСТ Р 52289, п. 5.4.22. Сами значения параметров в проект не записываются. Значения по умолчанию расстояний и скоростей (рисунки Б.33/Б.34, ГОСТ Р 52289, п. 5.2.2, ПДД, пп. 10.2/10.3) подставляются при создании проекта и смене местоположения; изменённые значения, расстояние до знака 1.25 вне диапазона п. 5.2.2 и шаг ступеней больше п. 5.4.22 выносятся в «Проверить вручную». Координаты размещения — эскизные, а не физические расстояния и не подтверждение применимости знаков.
- Пересборка удаляет только объекты с `generatedByTemplate: true`. Ручные объекты и уже изменённые объекты шаблона остаются; изменение параметров само по себе не перестраивает расстановку.
- Панель проверки и печать работают с применённым снимком. Маркеры расстояний подставляются только для введённых значений. Лист показывает коды знаков и выбранные поля ПУ-66 (`location`, `axisLabel`, `roadName`, `crossingWidthMetres`). Исходная книга, техническая таблица и исходный v1 JSON на лист не выводятся. Выпускной режим включается отметкой составителя и сбрасывается при любом изменении проекта; в файл проекта он не записывается.
- После применения правок на этапе «Знаки и объекты» редакции PNG можно закрепить явной кнопкой и сохранить проект. Лист и рабочая область используют исторические PNG из той же SQLite; при изменении набора использованных кодов закрепление очищается, поэтому закрепите их заново. Проекты без закрепления используют активный каталог. Знаки 3.24 с любой скоростью и таблички 8.1.1 с расстоянием рисуются программно и закрепления не требуют.

Ежегодная сверка ПУ-66 линейным подразделением ведётся в отдельном журнале локальной SQLite. Контрольная дата — 30 января, новая редакция карточки не наследует статус. Журнал не включён в JSON и лист.
