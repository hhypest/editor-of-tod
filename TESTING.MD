# Локальное тестирование

Руководство для проверки Vue-приложения на домашнем компьютере. Можно создать проект без прежнего файла, открыть JSON v1/v2/v3/v4, править параметры и объекты, закрепить ограниченные поля локальной ПУ-66, сохранить черновик в SQLite или скачать копию `schemaVersion: 4`. Условный черновой лист A4 можно распечатать через браузер для внутренней сверки. Реестры ПУ-66 и знаков остаются на компьютере составителя. Автосохранение, полный нормативный лист СОДД, отдельный экспорт PDF/PNG и согласование ещё не реализованы.

**Docker не нужен:** локальный сервер и SQLite запускаются вместе с приложением через Node.js. Нужны Node.js, npm и браузер; `compose.yml` не требуется.

## Подготовка

- Установите Git, Node.js 24 (не ниже 24.12.0) либо Node.js 26 (не ниже 26.7.0) и npm. В `.nvmrc` указана версия 24 для обычного запуска; проверить установленную версию можно командами `node --version` и `npm --version`.
- Откройте терминал (в Windows — PowerShell) и выполните команды ниже. Для первого запуска:

```bash
git clone https://github.com/hhypest/editor-of-tod.git
cd editor-of-tod
node --version
npm --version
npm ci
npm run dev
```

Если репозиторий уже скачан, откройте его каталог и перед проверкой выполните `git pull --ff-only`, затем `npm ci` и `npm run dev`. Откройте `http://127.0.0.1:5173/`: интерфейс работает на порту 5173, локальный API на 4100. Терминал с обоими процессами оставьте открытым; для остановки нажмите `Ctrl+C`. Первый `npm ci` скачивает зависимости из npm.

Открывайте приложение через адрес Vite, а не двойным щелчком по `index.html`. Запуск не требует проброса портов, учётной записи или внешней БД. Приложение слушает только `127.0.0.1`; другая машина в сети не получает к нему доступ. SQLite создаётся автоматически в `private-data/registry.sqlite` и остаётся на вашем компьютере. База и копии **не зашифрованы**: ограничьте доступ к ним средствами ОС и не помещайте реальные карточки в облачную синхронизацию без разрешения на такое хранение.

## Автоматические проверки

В другом терминале из каталога репозитория выполните:

```bash
npm run check
```

Команда последовательно проверяет форматирование, Oxlint, ESLint, типы TypeScript, прямой запуск локального API/CLI через Node.js с временной SQLite в памяти, тесты Vitest и сборку Vite. Ожидается код завершения `0`, все тесты проходят, сборка сообщает об успешном создании `dist/`. Отдельно проверку запуска можно выполнить командой `npm run check:runtime`, тесты — `npm run test`.

Остановите `npm run dev` и при необходимости проверьте собранную версию:

```bash
npm run build
npm run preview
```

Откройте `http://127.0.0.1:4173/` и повторите сценарии ниже. `preview` запускает и API, и просмотр сборки; он ничего не публикует. Для запуска собранного приложения через один локальный адрес выполните `npm run build`, затем `npm run local` и откройте `http://127.0.0.1:4100/`.

## Импорт XLSX ПУ-66 и архива знаков

Остановите `npm run dev` или `npm run local`. Поместите разрешённые XLSX и ZIP в каталог `local-input/` (он исключён из Git) либо передайте абсолютные пути. Не переименовывайте содержимое ZIP. В приведённых командах замените имена файлов на свои:

```bash
npm run import:pu66 -- "local-input/card-1.xlsx" "local-input/card-2.xlsx"
npm run import:pu66 -- --apply "local-input/card-1.xlsx" "local-input/card-2.xlsx"
npm run import:signs -- "local-input/signs.zip"
npm run import:signs -- --apply "local-input/signs.zip"
```

Без `--apply` команды только показывают количество новых, изменённых и неизменённых записей. С `--apply` каждая команда сперва создаёт копию в `private-data/backups/`, затем записывает пакет целиком. Повторите просмотр: те же файлы должны показывать только неизменённые записи. После запуска приложения нажмите «Обновить каталоги». Для предоставленных четырёх XLSX и ZIP ожидаются 4 карточки и 420 знаков. Исходные XLSX сохраняются внутри локальной SQLite; исходный ZIP целиком не сохраняется, но сохраняются обе версии PNG каждого знака.

При первом запуске новой версии существующая SQLite-база обновляется до версии 4: для старых баз версии 2 поле с автоматически трассированными SVG удаляется, файл уплотняется, затем создаются таблицы черновиков; база версии 3 получает только новые таблицы. Перед обновлением остановите приложение и сохраните копию `private-data/registry.sqlite` отдельно. Для уплотнения базы версии 2 нужно свободное место на диске. Старые резервные копии сохраняют своё содержимое. Версия 4 хранит исходные PNG знаков и полные снимки сохранённых проектов, включая исходный JSON; защищайте резервные копии так же, как основную базу.

Если скачана готовая приватная база, распакуйте `registry.sqlite` в `private-data/` **при остановленном приложении**, предварительно сохранив свою прежнюю базу и резервные копии. Затем запустите `npm run dev`. База содержит конфиденциальные данные, не шифруется приложением и не должна попадать в Git, публичные обращения или общий диск без разрешения.

Проверьте поиск по коду знака в каталоге и отображение PNG. Для вымышленного JSON из раздела ниже список использованных кодов сообщает, какие изображения доступны. Для карточки локальный экран показывает сводку составителю, а `/api/pu66/{ключ}/scheme` выдаёт только внутренний ключ, место, подпись оси, название дороги, ширину проезжей части, номер и время обновления редакции. Полный XLSX и техническая таблица через этот адрес не выдаются.

## Проверка предварительного выбора схемы

Введите длины фронта работ `29.9`, `30` и `30.1` м. Ожидаются соответственно Б.34, Б.33 и Б.33. Ровно `30` м сопровождается предупреждением: подписи к рисункам Б.33/Б.34 в ОДМ говорят «более» и «менее» 30 м, тогда как размерные обозначения на рисунках включают границу. Отнесение ровно 30 м к Б.33 — принятое правило этого проекта, требующее предметной сверки перед применением. Выбор по одной длине не подтверждает пригодность схемы для конкретного переезда, интенсивности, видимости и условий работ.

Создавайте копии обезличенного примера в текстовом редакторе и выбирайте их через то же поле. Исходный `manual-v1.json` оставьте без изменений.

## Проверка своего старого проекта

Экспортируйте JSON из автономного редактора и сохраните резервную копию до теста. Ключ `localStorage` старого HTML-прототипа напрямую этим приложением не читается: нужен именно сохранённый JSON-файл. Личные или служебные проекты храните в локальном каталоге `local-input/` или `private-data/` (оба исключены из Git), не добавляйте их в PR и публичные обращения.

Загрузите копию файла, прочитайте предупреждения, сохраните локальный черновик при необходимости, скачайте v4 и отдельно исходный JSON. Сопоставьте число объектов, номера знаков, реквизиты и значимые ручные правки с оригиналом. Сохранение v4 или черновика не заменяет исходный файл. Текущая координатная область не отображает дорогу, зону работ, размерные линии и реквизиты на полном листе и не печатает схему, поэтому её соответствие реальным условиям и нормативам необходимо проверять отдельно.

## Если что-то не работает

- `npm ci` показывает `EBADENGINE` с Node 26.7.0: обновите репозиторий командой `git pull --ff-only`, затем выполните `npm ci` снова. Начиная с исправления прямого запуска поддерживаются Node 24.12+ и 26.7+ в пределах соответствующих основных версий. Предупреждения `deprecated` для косвенных зависимостей сами по себе не останавливают установку.
- `npm run dev` сообщает `ERR_MODULE_NOT_FOUND` для `src/domain/model`: проверьте, что обновились `src/domain/local-projects.ts` и `src/domain/model.ts`, запустите `npm run check:runtime`. Эта проверка должна пройти до запуска интерфейса и не обращается к вашей рабочей SQLite.
- `node` или `npm` не распознаётся: завершите установку поддерживаемой версии Node.js и откройте новый терминал; проверьте `node --version`.
- `npm ci` сообщает о несовпадении `package.json` и lockfile: убедитесь, что вы на актуальной ветке `main` и локально не меняли эти файлы. Для теста используйте чистый клон.
- Страница не открывается: откройте `http://127.0.0.1:5173/` и проверьте, что оба процесса запущены. Порты 4100 и 5173 фиксированы: если один из них занят, остановите программу, занявшую порт, и повторите запуск. Для `preview` нужен свободный порт 4173.
- Блок реестров показывает ошибку: проверьте вывод локального API в терминале и наличие прав на запись в `private-data/`. Не прикладывайте файл базы к публичному обращению.
- Импорт не проходит: убедитесь, что выбран JSON проекта с `v: 1` или `schemaVersion: 2/3/4`, а не HTML-файл прототипа. Сверьте поле из сообщения об ошибке и проверьте исправный пример из репозитория.

При сообщении об ошибке полезно записать ОС, браузер, версии Node и npm, SHA коммита (`git rev-parse --short HEAD`), шаги воспроизведения, ожидаемый и фактический результат. Для публичного отчёта используйте обезличенный пример; не прикладывайте реальные карточки переездов, персональные данные и служебные файлы.
