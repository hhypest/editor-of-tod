# Локальное тестирование

Руководство для проверки текущего Vue-приложения на домашнем компьютере. Сейчас оно открывает JSON-проекты автономного редактора (`v: 1`), сохраняет копию в формате `schemaVersion: 2` и позволяет скачать исходный JSON. Редактор листа, проверка нормативов, печать и согласование ещё не реализованы.

**Docker не нужен:** серверная часть и база данных отсутствуют. Для запуска достаточно Node.js, npm и браузера; `compose.yml` на этом этапе не требуется.

## Подготовка

- Установите Git, Node.js 24 (не ниже 24.12.0) и npm. Версия Node указана в `.nvmrc`; проверить установку можно командами `node --version` и `npm --version`.
- Откройте терминал (в Windows — PowerShell) и выполните команды ниже. Для первого запуска:

```bash
git clone https://github.com/hhypest/editor-of-tod.git
cd editor-of-tod
node --version
npm --version
npm ci
npm run dev
```

Если репозиторий уже скачан, откройте его каталог и перед проверкой выполните `git pull --ff-only`, затем `npm ci` и `npm run dev`. Откройте в браузере адрес, напечатанный Vite в терминале (обычно `http://localhost:5173/`). Терминал с сервером оставьте открытым; для остановки нажмите `Ctrl+C`. Первый `npm ci` скачивает зависимости из npm.

Открывайте приложение через адрес Vite, а не двойным щелчком по `index.html`. Запуск на своём компьютере не требует проброса портов, учётной записи или подключения к БД.

## Автоматические проверки

В другом терминале из каталога репозитория выполните:

```bash
npm run check
```

Команда последовательно проверяет форматирование, Oxlint, ESLint, типы TypeScript, тесты Vitest и сборку Vite. Ожидается код завершения `0`, все тесты проходят, сборка сообщает об успешном создании `dist/`. Отдельно тесты можно запустить командой `npm run test`.

При необходимости проверьте собранную версию:

```bash
npm run build
npm run preview
```

Откройте адрес, который выведет `preview` (обычно `http://localhost:4173/`), и повторите сценарии ниже. Эта команда проверяет локальный просмотр сборки и ничего не публикует.

## Ручная проверка импорта

В репозитории есть обезличенный файл [`tests/fixtures/manual-v1.json`](tests/fixtures/manual-v1.json). Он содержит условный переезд `TEST-001`, вариант Б.33, одну стойку с двумя указаниями знаков и одну текстовую надпись. Данные вымышлены; файл годится для воспроизводимой проверки без рабочих материалов.

| Шаг | Действие                                                                                      | Ожидаемый результат                                                                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Откройте страницу и выберите `tests/fixtures/manual-v1.json` через поле «Файл проекта .json». | Появится блок «Структура проекта проверена», указаны `TEST-001`, `B33`, 2 объекта и 2 указания знаков. Появятся предупреждения о непроверенных сведениях и пустом расстоянии `d50`.  |
| 2   | Нажмите «Сохранить копию v2».                                                                 | Браузер скачает `scheme_TEST-001_v2.json`. В файле есть `schemaVersion: 2`, `crossing.referenceId: "TEST-001"`, два объекта `placements` и `source.originalJson` с исходным текстом. |
| 3   | Нажмите «Скачать исходный JSON».                                                              | Скачается `scheme_TEST-001_original_v1.json`. Его содержимое совпадает с выбранным `manual-v1.json`; исходный файл на диске не меняется.                                             |
| 4   | Выберите только что скачанный файл v2.                                                        | Страница покажет «Новый формат v2», прежний переезд, вариант и количество объектов. Кнопки скачивания остаются доступны; повторное открытие не меняет `id` и `createdAt` внутри v2.  |

Браузер может добавить номер в скобках к имени повторно скачанного файла. Импорт выполняется в браузере; JSON не отправляется на сервер приложения.

В разделе «Сверка перенесённых данных» сравните расстояния и реквизиты с исходным JSON, затем найдите объект `id: 2` с текстом «Ручная правка» и координатами `abs; x=810; y=605`. Эти числа описывают положение в SVG, не расстояния на местности.

Затем загрузите [`tests/fixtures/legacy-b34-manual.json`](tests/fixtures/legacy-b34-manual.json). Ожидаются `TEST-002`, `B34`, 4 объекта, 3 указания знаков и предупреждение об устаревшем счётчике. В таблице проверьте ручную стойку `id: 7` со сторонами `down/left`, знаками `3.24_40_ж` и `9.99`, привязкой `abs; x=912; y=44`; неизвестный номер знака переносится как текст без проверки каталога. Скачанный v2 должен содержать `nextPlacementId: 12`, а исходный JSON в `source.originalJson` — дополнительное поле `legacyNote`.

### Проверка ошибок

Создавайте копии обезличенного примера в текстовом редакторе и выбирайте их через то же поле. Исходный `manual-v1.json` оставьте без изменений.

| Изменение в копии                                         | Ожидаемая ошибка                                                                             |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Заменить значение `"d150": 150` на `"d150": "около 150"`. | «Расстояние «d150» должно быть числом». Результат прошлого успешного импорта скрывается.     |
| Заменить `"v": 1` на `"v": 7`.                            | Сообщение о неподдерживаемой версии (`v: 1` и `schemaVersion: 2` — поддерживаемые варианты). |
| Удалить закрывающую `}` в конце файла.                    | «Файл не содержит корректный JSON».                                                          |
| Заменить `"id": 2` у второго объекта на `"id": 1`.        | Сообщение о повторяющемся номере объекта.                                                    |

После каждого отказа вновь выберите исправный пример. Импорт должен снова завершиться успешно. Файл больше 10 МБ должен отклоняться сообщением «Файл проекта больше 10 МБ».

## Проверка своего старого проекта

Экспортируйте JSON из автономного редактора и сохраните резервную копию до теста. Ключ `localStorage` старого HTML-прототипа напрямую этим приложением не читается: нужен именно сохранённый JSON-файл. Личные или служебные проекты храните в локальном каталоге `local-input/` или `private-data/` (оба исключены из Git), не добавляйте их в PR и публичные обращения.

Загрузите копию файла, прочитайте предупреждения, скачайте v2 и отдельно исходный JSON. Сопоставьте число объектов, номера знаков, реквизиты и значимые ручные правки с оригиналом. Сохранение v2 не заменяет исходный файл. Текущий интерфейс не отображает и не печатает лист, поэтому геометрию и соответствие схеме движения пока нельзя подтвердить визуально в новом приложении.

## Если что-то не работает

- `node` или `npm` не распознаётся: завершите установку Node.js 24 и откройте новый терминал; проверьте `node --version`.
- `npm ci` сообщает о несовпадении `package.json` и lockfile: убедитесь, что вы на актуальной ветке `main` и локально не меняли эти файлы. Для теста используйте чистый клон.
- Страница не открывается: используйте точный адрес из вывода `npm run dev`; если порт занят, Vite может показать другой.
- Импорт не проходит: убедитесь, что выбран именно JSON проекта с `v: 1` или `schemaVersion: 2`, а не HTML-файл прототипа. Сверьте поле из сообщения об ошибке и проверьте исправный пример из репозитория.

При сообщении об ошибке полезно записать ОС, браузер, версии Node и npm, SHA коммита (`git rev-parse --short HEAD`), шаги воспроизведения, ожидаемый и фактический результат. Для публичного отчёта используйте обезличенный пример; не прикладывайте реальные карточки переездов, персональные данные и служебные файлы.
