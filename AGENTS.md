# Правила для автоматизированных изменений

- Прочитайте `README.md`, `CONTRIBUTING.md`, `ROADMAP.md` и относящиеся к задаче файлы в `docs/` перед изменением кода.
- В репозитории реализованы импорт старых JSON, редактирование проекта v10, явная ограниченная привязка ПУ-66, локальные SQLite-реестры, библиотека нормативных документов, подтверждение нормативных параметров, каталог знаков из PDF ГОСТ Р 52290, выпускной лист с PNG и переносной exe. Не описывайте функции автономного HTML как готовые функции Vue-приложения.
- Данные ПУ-66 конфиденциальны и хранятся только в `private-data/` на компьютере составителя. Никогда не добавляйте реальные карточки, локальную SQLite или резервные копии в GitHub.
- Архивы, изображения знаков, PDF стандартов и извлечённый из них текст также остаются в локальной базе. В публичных тестах допускаются только вымышленные карточки, нарисованные программно тестовые изображения и собранные программно PDF с вымышленным текстом.
- Не импортируйте содержимое локального HTML-прототипа, карточки ПУ-66, исходные PDF стандартов или их изображения в публичный репозиторий без подтверждённых прав и проверки допустимости публикации.
- Для правил размещения знаков указывайте редакцию и пункт нормативного источника. Выбор Б.33 при ровно 30 м — решение проекта: подписи рисунков ОДМ и размерные обозначения расходятся, требуется предметная сверка. Не превращайте примеры в универсальные нормы без проверки.
- Сохраняйте совместимость старых JSON-проектов (`v: 1`, `schemaVersion` 2–9) через версионируемый импорт.
- Новые зависимости, входящие в программу, — только с разрешительными лицензиями (`ALLOWED_LICENSES` в `scripts/third-party-licenses.ts`; см. `docs/licensing.md`). Не отключайте проверку лицензий при сборке и не убирайте файлы лицензий из дистрибутива.
- Регулирование Б.34: знаки при потоке строго менее 250 авт/ч и участке менее 50 м с обеспеченной видимостью; 250–500 включительно — один только при условиях ОДМ, п. 13.7.5; свыше 500, ограниченная видимость и Б.33 — два. Пороги берутся из существующих параметров ГОСТ/ОДМ; отдельного подтверждаемого профиля переезда нет. Таблица Д.1 задаёт применение знаков/светофоров, а не количество персонала; Е.1/Е.2 относятся к скорости. Изменение оснований снимает отметки проверки. Число и положение регулировщиков на листе — условие выпуска, а не отметка составителя (два — по табл. 5 ОДМ и разные стороны рабочей зоны; один — только число, его место нормативно не сверено).
- Первый блок ПДД: код «ПДД», дата редакции и дата введения разделены; без последней ПДД не становится действующим источником. Справочник скорости задаёт условия явно и сохраняет их в v9, но не удостоверяет скорость всего потока. Все связанные действующие изменения ПДД входят в основания. Исторические снимки скорости/регулирования записываются явным действием и не обновляются при смене источников; устаревшая запись блокирует свою отметку до новой записи. Остаток П3 (отгон и полный выпускной профиль) требует отдельного блока.
- Стойка с расстоянием (v10, ADR-0008): место на листе и подпись выводятся из `distance`, лист остаётся без масштаба. Миграция не сдвигает стойки прежних проектов; не выводите расстояния на местности из координат листа.
- Числа нормативных правил задавайте нормативными параметрами с документом и пунктом (`src/domain/normative-parameters.ts`), а не константами в расчётах.
- Используйте `npm run check` перед PR. Добавляйте предметные тесты при изменении расчётов, импорта, экспорта и шаблонов.
- Обновляйте документацию и changelog при изменении поведения пользователя. Не публикуйте и не разворачивайте приложение автоматически; сборка exe (`windows-exe.yml`) запускается только вручную.
