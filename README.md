# Редактор СОДД для железнодорожных переездов

Локальное приложение для подготовки схем организации дорожного движения при текущем ремонте железнодорожных переездов. Один составитель работает на своём компьютере; интерфейс написан на Vue 3 и TypeScript, данные хранятся в SQLite. Есть переносная программа для Windows и запуск из исходного кода. Архитектурное направление — [модульный монолит с DDD и Clean Architecture](docs/architecture.md#закреплённый-архитектурный-подход); [выбор Vue и отказ от перехода на React/Angular](docs/adr/0009-vue-ui-framework.md) обоснованы отдельным ADR.

**Статус:** `0.3.0-dev` после [выпуска 0.2.0](https://github.com/hhypest/editor-of-tod/releases/tag/0.2.0). Технический этап завершён и принят. В первой приёмке 29.10.2026 на a5ad72f приняты поля ПУ-66 (#110) и перенос из прежнего HTML (#108); блок длины и фронта (#103) возвращён на доработку. Подготовлены исправления подстановки, длинного частичного Б.34 и запрета превышения предела. Повторная приёмка новой сборки, примыкания (#107) и эталоны (#109) остаются открытыми. [Результат первой приёмки](docs/acceptance-0.3.0-2026-10-29.md) · [Текущая очередь и условия завершения](ROADMAP.md) · [Протокол технической регрессии](docs/refactoring/technical-regression-2026-10-28.md). Программа не удостоверяет соответствие схемы нормам и не заменяет согласование.

## Возможности

- Создание проекта по карточке ПУ-66 и открытие старых файлов JSON; текущий формат проекта — v11. У стойки задаётся расстояние до начала работ в метрах, её место на листе и подпись следуют из него. Условия скорости и явно записанные основания решений сохраняются вместе с проектом; смена источников требует новой сверки.
- Пошаговое заполнение параметров, сборка шаблонов Б.33/Б.34, ручная правка объектов, отмена и повтор.
- Закреплённый снимок ПУ-66 содержит участок/станцию и значения видимости по направлениям и годам. Обновление локальной карточки не переписывает проект; новые сведения выбираются после сравнения.
- Локальные реестры ПУ-66 и знаков, библиотека PDF нормативных документов, подтверждение параметров по источникам.
- Обратимое исключение ПУ-66 с историей и преемником; проекты сохраняют прежние снимки данных.
- Сохранённые проекты с историей версий и отдельные копии восстановления неприменённого ввода с защитой от открытия и удаления другим работающим окном.
- Лист A4: предпросмотр, печать через браузер, выпускной режим после проверки составителем и выгрузка PNG. Выпуск закрыт, пока не заполнены условия работ и расстояния стоек и пока регулировщики на листе не соответствуют способу пропуска.
- Перед обновлением схемы базы программа сама сохраняет прежний файл; повторный запуск открывает уже работающую программу, а не вторую.

Редактирование непосредственно на печатном листе, примыкания и процесс согласования ещё запланированы. Актуальные задачи и критерии готовности находятся в [дорожной карте](ROADMAP.md). Возможности прежнего автономного HTML описаны отдельно в [документе о переносе](docs/migration.md).

## Начать работу

**Составителю:** используйте подготовленный `editor-of-tod.exe` для Windows. Порядок запуска, первоначальной настройки, сохранения и резервного копирования — в [руководстве составителя](docs/getting-started.md). В программе также есть контекстная справка.

**Для запуска из исходников:** нужны Git, npm и Node.js 24 от 24.12.0 либо Node.js 26 от 26.7.0.

```bash
git clone https://github.com/hhypest/editor-of-tod.git
cd editor-of-tod
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173/` и оставьте терминал работающим. Команда запускает интерфейс и локальный API; база создаётся автоматически. Docker и внешняя СУБД не требуются. Остальные команды, сборка exe и переменные окружения — в [руководстве разработчика](docs/development.md).

При первом запуске отдельная настройка ведёт через четыре шага: ГОСТ и знаки, книги ПУ-66, документы для правил и подтверждение параметров. Выбор, просмотр и запись выполняются внутри шагов; «Назад» и «Далее» остаются внизу экрана. После настройки открываются проекты. Без карточки ПУ-66 новый проект не создаётся. Дальнейшая переработка интерфейса описана в [плане рабочих сценариев](docs/interface-workflows.md).

## Данные и права

Рабочие ПУ-66, PDF стандартов, изображения знаков, проекты и резервные копии остаются на компьютере составителя. В GitHub их не добавляют. База создаётся в `private-data/`; расположение данных Windows-программы указано в её консоли. База и копии не зашифрованы, доступ к ним ограничивается средствами ОС и правилами организации.

Скачивание JSON не заменяет сохранение проекта в базу. Проекты, листы и резервные копии могут содержать отобранные сведения ПУ-66 и требуют соответствующего обращения. Подробнее: [реестр ПУ-66](docs/pu66-data.md) и [контракт проекта](docs/scheme-format.md).

Обеспечение прав на используемую графику знаков относится к организации, использующей ПО, и техническому специалисту; это вне ответственности репозитория и разработчика. [Решение по #111](docs/licensing.md#ответственность-за-графику-знаков).
