# Редактор СОДД для железнодорожных переездов

Веб-приложение для подготовки схем организации дорожного движения на период текущих работ на железнодорожных переездах. Проект развивается из автономного HTML-прототипа в платформу на Vue 3 и TypeScript. Схемы предполагается передавать для рассмотрения владельцу автомобильной дороги, органам местного самоуправления и Госавтоинспекции по применимой для конкретных работ процедуре.

**Состояние проекта:** работает импорт JSON-проектов автономного редактора, просмотр перенесённых данных и сохранение копии `schemaVersion: 2`. Есть локальные SQLite-реестры ПУ-66, нормативных пунктов и знаков, импорт XLSX/ZIP с компьютера составителя, каталог изображений и предварительный выбор Б.33/Б.34 по длине фронта работ. Редактор листа, размещение знаков, печать и согласование ещё не реализованы. Код и встроенные данные прототипа не опубликованы в репозитории.

## Что есть в исходном прототипе

Локальный файл `Схемы_ОДД_переезды.html` содержит варианты Б.33 и Б.34 ОДМ 218.6.019-2016, 73 записи о переездах, 420 изображений знаков, редактирование объектов на SVG-листе, сохранение и открытие JSON-проекта, автосохранение, отмену действий, печать A4/PDF и экспорт PNG. Руководство пользователя описывает эти возможности. Перечисление относится к **прототипу**, а не к приложению из этого репозитория.

При переносе функций требуется сохранить возможность открыть ранее сохранённый проект без потери важных правок, проверить нормативные правила и определить происхождение каждого набора данных и изображения. См. [план миграции](docs/migration.md) и [нормативную основу](docs/standards.md).

## Локальный запуск

Нужен Node.js 24.12 или новее в пределах версии 24 (версия указана в `.nvmrc`) и npm.

```bash
npm ci
npm run dev
```

Откройте адрес Vite из терминала (`http://127.0.0.1:5173/`). Команда запускает интерфейс и локальный API на `127.0.0.1:4100`; оба доступны только с этого компьютера. Для работы с собранной версией: `npm run build`, затем `npm run local` и адрес `http://127.0.0.1:4100/`. Docker и внешняя база не нужны.

SQLite создаётся в `private-data/registry.sqlite`; каталог исключён из Git. Кнопка резервного копирования сохраняет согласованную копию в `private-data/backups/`. Файл **не зашифрован**: ограничьте доступ средствами операционной системы и храните резервные копии по правилам работы с конфиденциальными данными. Не добавляйте файл или выдержки ПУ-66 в коммиты, PR, публичные сообщения и вложения. В базе пока хранятся карточки, краткие записи об источниках и история их правок; импорт JSON-проектов не записывает карточки автоматически.

Для загрузки разрешённых файлов сначала остановите приложение, затем выполните предварительный просмотр и импорт:

```bash
npm run import:pu66 -- "local-input/card-1.xlsx" "local-input/card-2.xlsx"
npm run import:pu66 -- --apply "local-input/card-1.xlsx" "local-input/card-2.xlsx"
npm run import:signs -- "local-input/signs.zip"
npm run import:signs -- --apply --vector "local-input/signs.zip"
```

Первый запуск каждой команды только сообщает количество новых и изменённых записей. `--apply` сохраняет их с резервной копией; повторная загрузка того же файла не создаёт новую редакцию. Оригинал каждой ПУ-66 и полная извлечённая таблица остаются только в SQLite. Локальный интерфейс показывает краткую сводку; отдельный API для будущего листа выдаёт лишь место, осевую подпись, название дороги и ширину проезжей части. Знаки хранятся как две версии PNG (с номером и без); `--vector` дополнительно трассирует версию без номера в SVG. Трассировка приблизительна, поэтому исходный PNG остаётся основным изображением. См. [инструкцию проверки](TESTING.MD) и [каталог знаков](docs/sign-catalog.md).

Команды разработки:

| Команда                | Назначение                                                  |
| ---------------------- | ----------------------------------------------------------- |
| `npm run dev`          | Vite и локальный API с SQLite на `127.0.0.1`                |
| `npm run local`        | Собранное приложение и API на `127.0.0.1:4100`              |
| `npm run import:pu66`  | Просмотр или импорт карточек XLSX в локальную SQLite        |
| `npm run import:signs` | Просмотр или импорт PNG из ZIP, при желании трассировка SVG |
| `npm run check`        | Форматирование, линтеры, типы, тесты и сборка               |
| `npm run test`         | Проверки модели и импорта проектов                          |
| `npm run format`       | Форматирование исходников и документации                    |
| `npm run lint:fix`     | Автоматическое исправление части замечаний линтеров         |
| `npm run build`        | Проверка типов и сборка в `dist/`                           |
| `npm run preview`      | Локальный просмотр собранной версии                         |

Версии зависимостей зафиксированы в `package-lock.json`; в CI выполняется `npm ci` и `npm run check`. Автоматическая публикация отсутствует: даже после сборки схема не считается проверенной или согласованной.

## Структура и процесс

- `src/domain/` — схемы данных, проверка JSON и миграция `v: 1` → `schemaVersion: 2`.
- `src/App.vue` — интерфейс локального импорта, сверки данных и скачивания копий.
- `src/components/` — просмотр и ручное ведение локальных реестров, каталог знаков, предварительный выбор варианта.
- `server/` — локальный API, импорт XLSX/ZIP и SQLite; конфиденциальные данные остаются в `private-data/`.
- `docs/scheme-format.md` — контракт нового файла и ограничения текущего импорта.
- `docs/migration.md` — инвентаризация автономного редактора и требования к совместимости.
- `docs/architecture.md` — границы модулей и модель будущей платформы.
- `docs/standards.md` — реестр нормативных источников и правила их проверки.
- `docs/pu66-data.md` — проект процедуры подготовки данных ПУ-66 для будущего каталога.
- `docs/sign-catalog.md` — формат локального каталога изображений и ограничения трассировки.
- [`ROADMAP.md`](ROADMAP.md) — очередность работ и критерии готовности.
- [`CONTRIBUTING.md`](CONTRIBUTING.md) — правила кода, проверок и изменений.
- [`TESTING.MD`](TESTING.MD) — локальный запуск и проверка импорта на обезличенном примере.
- [шаблон PR](.github/PULL_REQUEST_TEMPLATE.md) — что приложить к ревью.
- [`CHANGELOG.md`](CHANGELOG.md) — история изменений репозитория.

Изменения вносятся через ветку и pull request. Для шаблонов, знаков, расстояний и экспортируемого листа к PR прикладываются проверяемые примеры и ссылка на конкретную редакцию источника. Предметную корректность схемы оценивает ответственный специалист перед передачей на согласование.

## Данные и права

Исходный HTML содержит встроенные записи из карточек ПУ-66, изображения знаков и реквизиты организации. Исходные PDF стандартов и руководство пользователя также предоставлены для анализа. Эти материалы **не входят** в открытый репозиторий и **не подпадают** под его лицензию MIT. Перед публикацией любого набора переездов, изображения, полного текста стандарта или исходного прототипа отдельно проверяются права и допустимость раскрытия. Для локальных материалов предусмотрены игнорируемые каталоги `local-input/` и `private-data/`.

Импорт проверяет структуру файла, сохраняет исходный JSON внутри новой копии, показывает перенесённые поля и предупреждения. Файл проекта обрабатывается в браузере; карточки реестров сохраняются локальным API в SQLite на том же компьютере. База не синхронизируется с GitHub. Приложение пока не проверяет соответствие схемы нормативам и не заменяет установленный порядок согласования.
